## Step 7 — sign-out clears the image buffer ✅

Staged correctly by stopping **MinIO** (NOT the API) — the API must stay up or the client's
`AckGate` closes and no capture happens at all (see Finding). API up → gate open → capture
succeeds; MinIO down → `POST /v1/screenshots` 5xx (`putStream` throws before the DB row) →
client classifies transient → retains the file.

```
22:37:52  capture buffered: screenshots/1784306272087__019f70f1-0757-71ce-9bae-e57809f77476.jpg  (269 KB)
          (upload 5xx against dead MinIO; retries keep failing, file retained)
          -> Sign out
22:40:18  screenshots/ emptied (1 -> 0), MinIO still down
```

With MinIO down the whole time, the file could not have uploaded-and-deleted — an empty dir
can only be the sign-out teardown (`finishInFlight()` then `ImageBufferStore.clear()`). The
buffered shot `019f70f1-...` **never appears in the DB** (4 READY rows above, none is it),
confirming it could not upload under the next user's token.

## Finding — plan Step 7 hint is incompatible with the shipped AckGate

The plan's Step 7 hint "stop the API briefly to force a transient" cannot buffer a screenshot.
`AckGate.withCaptureAllowed` fetches effective policy from the API on every capture tick with
no offline cache, so an unreachable API closes the gate and suppresses capture entirely
(observed: two 7-min API-down windows, zero captures). The clock keeps running because
auto-tracking uses an offline AckMarker and is not a capture path. Correct staging is
**stop MinIO, keep the API up**. (Also: `MinioService.onModuleInit` CreateBucket throws
uncaught when MinIO is down, so the API only boots while MinIO is up — restart the API before
stopping MinIO.)
