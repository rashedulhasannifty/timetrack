# Slice 3.2 — Streaming CSV export — Design

**Date:** 2026-07-19
**Phase:** 3 — Reporting + approvals (`docs/plans/phase-3-reporting-approvals.md` §3.2)
**PRD:** §6.5 (reports), §7.8 (report endpoints)

## Goal

A MANAGER/ADMIN exports a filterable, date-range CSV of **individual time entries** for
billing/payroll. Rows stream from Postgres via keyset pagination → an async generator → the
HTTP response, so the full result set is **never held in memory**.

The `GET /v1/reports/export.csv` route and a `NotImplementedException` service stub already
exist from the slice-3.1 scaffold; this slice implements them.

## Row shape — one row per time entry

Fixed column order, defined as a **single exported constant** in the module so the CSV writer
and the e2e header assertion share one source of truth:

```
entryId,user,project,task,startTime,endTime,durationSeconds,source,note
```

- `user` = user name; `project` = project name or empty; `task` = task name or empty;
  `note` = entry note or empty. `entryId` = `time_entries.id` (client-minted UUIDv7).
- `source` = `MANUAL` | `AUTO`.

### Time semantics — window-clamped (decided)

`startTime`/`endTime` are **trimmed to `[from, to]`**, and `durationSeconds` is the clamped
duration. Consequences:

- `end − start == durationSeconds` on **every** row — no row looks self-contradictory when
  opened in a spreadsheet.
- The CSV's `durationSeconds` total **reconciles** with the `/reports` team-summary totals
  (which clamp identically).
- A boundary-crossing entry shows its trimmed edges, not its true recorded edges.
- A **running** entry (`endTime IS NULL`) → empty `endTime` column, `durationSeconds` computed
  to `now()` (clamped to `to`).

### Selection predicate

Entries **overlapping** the window for the scoped users — identical to the reports aggregates:

```sql
te."startTime" < :to AND COALESCE(te."endTime", now()) > :from
```

## CSV formatting — `csv-writer.ts` (pure, unit-tested)

- **RFC 4180:** `CRLF` (`\r\n`) line endings. A field is wrapped in double quotes iff it
  contains `,` `"` `CR` or `LF`; any internal `"` is doubled.
- **Formula-injection neutralization (decided):** a **text** field (`user`/`project`/`task`/
  `note`) whose first character is one of `= + - @ TAB(0x09) CR(0x0D)` gets a single leading
  `'` prepended **before** RFC-4180 escaping (OWASP CSV-injection guidance). Numeric / ISO-8601
  / enum columns are structurally safe and are not neutralized.
- **No UTF-8 BOM.** Keeps the header assertion exact (`entryId…`, not `﻿entryId…`). Add a
  BOM later only if Excel encoding is reported as a real problem.

## Streaming path (the slice's core risk — de-risked first)

There is **no existing streaming precedent** in this API. The "never buffer" requirement is the
one thing that can silently regress while every test still passes (a buffered CSV is
byte-identical to a streamed one), so the mechanism is proven with a throwaway spike **before**
the implementation plan is finalized.

1. **Repository — `async *streamEntries(scope, from, to, projectId?)`:** keyset pagination on
   `(te."startTime", te.id)`, `LIMIT 500` per `$queryRaw`, looping until a short page is
   returned. `JOIN users`, `LEFT JOIN projects`, `LEFT JOIN tasks`. Reuses the existing
   `scopeSql()` helper for user/team/all scoping. Yields plain row objects; never buffers the
   whole set.
2. **Service — `exportCsv(query, user)`:** **awaits `resolveScope` first** so a 403 is thrown
   _before any byte is written_, then returns an async iterable that yields the header line
   followed by one formatted line per repository row.
3. **Controller:** `Readable.from(iterable, { objectMode: false })` (byte mode — the generator
   yields `string`s) → `new StreamableFile(stream, { type: 'text/csv; charset=utf-8',
disposition: 'attachment; filename="timetrack-export-<from>_<to>.csv"' })`. The class-level
   `@Roles('MANAGER','ADMIN')` already gates EMPLOYEE out.

**Spike gate:** seed rows spanning several batches and confirm either the batched query
round-trips or incremental flush, in byte mode. If `StreamableFile` fights the Fastify adapter,
the documented fallback is `@Res()` + writing lines to `reply.raw` in the loop (simpler byte
semantics, at the cost of the Nest interceptor lifecycle). This choice is locked before the
plan is written.

### Error semantics

- **All 4xx before the first byte:** Zod validation (pipe, pre-handler), `RolesGuard`, and
  `resolveScope` (403) all fire before streaming starts → clean RFC 9457 problem+json via the
  global filter.
- A **mid-stream** DB failure yields a **truncated** file. This is acceptable and inherent to
  streaming; nothing that could be surfaced cleanly is deferred into the generator.

## Dashboard

- **Next Route Handler — `app/(app)/reports/export/route.ts` (GET):** reads `getSession()`
  server-side, forwards `from`/`to`/`teamId`/`userId`/`projectId` to `/v1/reports/export.csv`
  with the bearer token, and returns `new Response(apiRes.body, { headers })` — piping the
  upstream stream straight through. The access token **stays server-side**; the browser never
  holds it (CLAUDE.md §4). A non-2xx upstream status is propagated.
- **"Export CSV"** is a plain `<a href="/reports/export?from=…&to=…&teamId=…">` on `/reports`,
  carrying the current filters. No `'use client'` — it is a server-rendered anchor.

## Contracts

**No new contract.** The query reuses `ReportRangeQuerySchema` (`from`, `to`, optional
`userId`/`projectId`/`teamId`). CSV is not a JSON DTO the dashboard parses — it downloads a
blob — so the row shape stays internal to the reports module. The column list lives as a single
named constant (see above) so the writer and tests cannot drift.

## Authorization

Same scope resolution as the rest of `/reports` (`ReportsService.resolveScope`):

- EMPLOYEE → 403 (class-level `@Roles('MANAGER','ADMIN')`).
- MANAGER → own team only; a `teamId` for another team → 403.
- ADMIN → any team, or no filter → all users.
- `userId` filter → `assertCanAccessUser` (self / manager-of-team / admin), else 403.

## Testing

- **Unit — `csv-writer.spec.ts`:** RFC-4180 escaping (comma, quote, embedded CRLF), formula
  neutralization (`=`,`+`,`-`,`@`, tab, CR — and that a safe leading char is untouched), empty
  optional fields.
- **Integration/e2e — `reports.e2e-spec.ts`** (`pnpm test:coverage`, `RUN_E2E=1` + Docker):
  - header line exact;
  - correct rows for a seeded fixture;
  - **empty / single-batch / multi-batch** result sets — the multi-batch case forces the
    keyset loop's continuation (batch size lowered or fixture > 500 rows);
  - filter application (`userId`, `projectId`, `teamId`);
  - boundary-crossing and running-entry clamping (`end − start == durationSeconds`);
  - **403** cross-team MANAGER; **401** unauthenticated.
- Coverage gate is `test:coverage` (combined unit+e2e), **not** `pnpm test`; `functions` is the
  binding metric. The generator's branches (empty, single, multi-batch) are covered explicitly.

## Out of scope

- Aggregated (per-user / per-user-per-day) CSV shapes — this slice is per-entry only.
- Async/background export jobs — the streaming synchronous endpoint is sufficient at current
  data scale.
- New contract schemas — none needed.
