# Slice 4.2 — Audit-log UI — design

**Phase:** 4 (SSO + admin + retention). **PRD:** §6.6 (admin/settings).
**Plan slice:** `docs/plans/phase-4-sso-admin.md` §4.2.

**Goal:** make the audit trail browsable — an ADMIN-only dashboard page that lists
`AuditLog` rows, filters them, pages through them with a stable cursor, resolves the
actor to a person, and lets an admin drill into any row's `diff`.

---

## 0. Starting point (what already exists)

- **Contracts** (`packages/contracts/src/admin.ts`): `AuditLogEntrySchema`
  (`id, actorId, action, targetType, targetId, diff: unknown|null, timestamp`),
  `AuditLogQuerySchema` (`targetType?, targetId?, from?, to?` — no pagination),
  `SYSTEM_ACTOR_ID` (nil UUID). No list/response wrapper.
- **API** (`apps/api/src/modules/admin/`): `GET /v1/admin/audit-log` is implemented and
  ADMIN-only (class-level `@Controller('admin')` + `@Roles('ADMIN')`). Controller validates
  the query with `ZodValidationPipe(AuditLogQuerySchema)`; service passes through; repository
  builds a `where` from the filters, `orderBy: { timestamp: 'desc' }`, `take: 500`, returns a
  bare `AuditLogEntry[]`. The actor is returned as a **raw UUID** — never resolved.
- **DB** (`packages/db/prisma/schema.prisma`): `model AuditLog { id, actorId, action,
targetType, targetId, diff: Json?, timestamp }`, only index `@@index([targetType, targetId])`
  — **no index on `timestamp`** despite ordering by it. `actorId` is a plain `String` — **no FK**
  to `User`.
- **Write sites (10):** `project.create/task.create/project.archive|unarchive`,
  `user.deactivate|reactivate/user.ack_monitoring`, `screenshot.redact`, `time_entry.edit`
  (`{before, after}`), `timesheet.decide` (`{from, to, note}`), `team.update_settings`
  (`{before, after}`), and worker `retention.cleanup` (nested per-table report, actor =
  `SYSTEM_ACTOR_ID`). **`diff` is heterogeneous**; `targetType` casing is inconsistent
  (`team`/`user` vs `TimesheetApproval`).
- **Dashboard:** `(app)/admin/audit/page.tsx` is a **placeholder** (header + "Scaffold. Admin
  only."). No fetch, no gate, no nav link. `api-client.ts` has **no** audit method. The
  approvals page (`(app)/approvals/page.tsx`) is the established server-rendered, searchParams-
  filtered, actor-name-resolved list pattern to copy.

This slice does **not** need to create the endpoint, module, or model — it enriches them and
builds the UI.

---

## 1. Decisions (settled during brainstorming)

1. **Pagination — cursor/keyset.** Keyset on `(timestamp desc, id desc)`; opaque cursor = the
   last returned row's `id`; response envelope `{ items, nextCursor }`; bounded `limit`. Chosen
   over offset (no drift as rows arrive, no costly `count()`) and over "no pagination" (the plan
   mandates it, and a 500-cap can't reach older rows within a filter).
2. **Actor display — resolve to name/email.** The API attaches `actorName`/`actorEmail` to each
   list item via one extra query. UI renders `System` for `SYSTEM_ACTOR_ID`, `name (email)` when
   resolved, and falls back to the raw UUID when the actor no longer exists (deactivated/erased).
3. **Diff drill-in — expandable row, generic pretty JSON.** Click a row to expand an inline panel
   showing formatted JSON of `diff`. One renderer handles every action shape (flat, before/after,
   nested). No per-action code, no separate detail page.

## 2. Contracts (`packages/contracts/src/admin.ts`)

Presentation fields live in **separate** schemas so the base `AuditLogEntrySchema` shared by the
10 write sites stays free of UI concerns.

```ts
// The list item the audit UI consumes: base entry + resolved actor identity.
export const AuditLogListItemSchema = AuditLogEntrySchema.extend({
  actorName: z.string().nullable(), // null when actorId doesn't resolve to a live User
  actorEmail: z.string().nullable(),
});
export type AuditLogListItem = z.infer<typeof AuditLogListItemSchema>;

// One page of the audit log. nextCursor is the id to pass back for the next page, or null at end.
export const AuditLogPageSchema = z.object({
  items: z.array(AuditLogListItemSchema),
  nextCursor: z.uuid().nullable(),
});
export type AuditLogPage = z.infer<typeof AuditLogPageSchema>;
```

`AuditLogQuerySchema` gains pagination inputs (query strings → coerced):

```ts
export const AuditLogQuerySchema = z.object({
  targetType: z.string().optional(),
  targetId: z.string().optional(),
  from: z.iso.datetime().optional(),
  to: z.iso.datetime().optional(),
  limit: z.coerce.number().int().min(1).max(100).default(50),
  cursor: z.uuid().optional(), // last-seen row id; validates for free since the cursor IS a uuid
});
```

### Response-shape change to `/v1/admin/audit-log` — why it's safe

The route changes from returning a bare `AuditLogEntry[]` to `AuditLogPage` (`{ items, nextCursor }`),
and each item gains `actorName`/`actorEmail`. CLAUDE.md says "never break `/v1`", but the rationale
is the **pinned, un-rollback-able Mac client**, which never calls `/admin/audit-log`. The only
consumers are the dashboard and the API's own tests — both ship in lockstep with this change. No
released client pins this route, so enriching its shape in place (rather than minting `/v2`) is
correct. This reasoning is recorded so review does not flag a v1 break.

## 3. API (`apps/api/src/modules/admin/`)

**Controller** — return type becomes `AuditLogPage`; validation pipe unchanged (still
`ZodValidationPipe(AuditLogQuerySchema)`, now carrying `limit`/`cursor`). Route, `@Roles('ADMIN')`,
and `/v1` mount are unchanged.

**Service** — still a thin passthrough to the repository.

**Repository** — two queries, both here (no Prisma in controller/service):

1. **Page query (keyset):**

   ```ts
   const rows = await this.prisma.auditLog.findMany({
     where, // targetType / targetId / timestamp gte-lte (unchanged)
     orderBy: [{ timestamp: 'desc' }, { id: 'desc' }],
     ...(cursor ? { cursor: { id: cursor }, skip: 1 } : {}),
     take: limit + 1, // the extra row tells us whether a next page exists
     select: { id, actorId, action, targetType, targetId, diff, timestamp },
   });
   const hasMore = rows.length > limit;
   const page = hasMore ? rows.slice(0, limit) : rows;
   const nextCursor = hasMore ? page[page.length - 1].id : null;
   ```

   Ordering by `(timestamp desc, id desc)` with `id` in the `orderBy` makes the Prisma `cursor: {id}`
   deterministic even when many rows share a `timestamp`. `select` stays explicit (never `*`).

2. **Actor resolution (one query, not N+1):**
   ```ts
   const actorIds = [...new Set(page.map((r) => r.actorId))];
   const users = await this.prisma.user.findMany({
     where: { id: { in: actorIds } },
     select: { id: true, name: true, email: true },
   });
   const byId = new Map(users.map((u) => [u.id, u]));
   // attach actorName/actorEmail = byId.get(r.actorId)?.name/email ?? null
   ```
   `SYSTEM_ACTOR_ID` matches no `User` row, so its name/email resolve to `null` naturally; the UI
   labels it "System". Deactivated/erased actors also resolve to `null` → UI shows the UUID.
   The repository returns `{ items, nextCursor }`; the "System"/UUID-fallback **labeling stays in
   the dashboard**, not the repository.

**Timestamp is coerced to ISO** (`toISOString()`) as today.

### Schema + migration (same commit)

Add a composite index matching the sort so keyset paging is index-served:

```prisma
model AuditLog {
  // ...unchanged fields...
  @@index([targetType, targetId])
  @@index([timestamp, id])   // NEW — serves orderBy (timestamp desc, id desc)
  @@map("audit_log")
}
```

Plain b-tree index — `prisma migrate dev` scaffolds it normally (this is **not** the partial/WHERE-
index case that Prisma's differ misses). Schema change + generated migration committed together.

## 4. Dashboard (`apps/dashboard/src/`)

### `api-client.ts`

Add one method (the only file that knows the API base URL; parses the response with the schema):

```ts
listAudit: (token: string, params: URLSearchParams) =>
  get(`/admin/audit-log?${params.toString()}`, AuditLogPageSchema, token),
```

Import `AuditLogPageSchema` from `@timetrack/contracts`.

### `lib/audit-view.ts` (pure, unit-tested)

Node-env vitest can only test pure transforms (no jsdom), so all formatting lives here:

- `actorLabel(item: { actorId, actorName, actorEmail }): string` —
  `SYSTEM_ACTOR_ID` → `"System"`; `actorName` present → `"<name> (<email>)"` (email omitted if
  null); otherwise the raw `actorId`.
- `formatDiff(diff: unknown): string` — `JSON.stringify(diff, null, 2)`; `null`/`undefined` →
  `"—"`. (Rendering/styling is the component's job; this returns the text.)
- `buildAuditParams(filters, cursor): URLSearchParams` — assembles `targetType/targetId/from/to/
cursor`, omitting empties. Used by both the page fetch and the "Next" link href.

### `(app)/admin/audit/page.tsx` (Server Component — replaces the placeholder)

Mirrors the approvals page:

```ts
export default async function AuditPage({
  searchParams,
}: { searchParams: Promise<{ targetType?: string; targetId?: string; from?: string; to?: string; cursor?: string }> }) {
  const session = await getSession();
  if (!session) return null;                       // layout already redirected
  if (session.role !== 'ADMIN') return <Forbidden />;

  const sp = await searchParams;
  const params = buildAuditParams(sp, sp.cursor);
  const page = await api.listAudit(session.accessToken, params);   // ApiError(403) → <Forbidden/> guard by role already covers it
  // render: filter <form method="get">, table, expandable diff rows, Next link
}
```

- **Filter form:** native `<form method="get">` with inputs for `targetType`, `targetId`, `from`,
  `to` (date-times) + submit. Submitting navigates to the same route with new query params. A filter
  change starts a fresh page (no `cursor` carried), because a submit form only includes its own
  fields — the stale cursor is dropped naturally.
- **Table columns:** Time (ISO/local), Actor (`actorLabel`), Action, Target (`targetType`/`targetId`),
  and an expand affordance.
- **Diff expand:** a small `'use client'` toggle component (`<AuditRow>` or a `<DiffToggle>`) that
  reveals a `<pre>` of `formatDiff(item.diff)`. This is the only client component.
- **Next link:** `page.nextCursor` present → `<a href={`?${buildAuditParams(sp, page.nextCursor)}`}>Next</a>`;
  absent → no link / disabled. Browser Back gives Prev. Empty page → "No audit entries."

### `layout.tsx`

Add `{ href: '/admin/audit', label: 'Audit log' }` to the `NAV` array. (Non-admins who follow it
hit the page-level `<Forbidden/>` — nav visibility is intentionally not role-gated here, matching
the existing `/admin/settings` link.)

## 5. Testing

- **Contracts (unit, no DB):** `AuditLogListItemSchema` accepts a base entry + nullable
  `actorName`/`actorEmail`; `AuditLogPageSchema` accepts `{ items, nextCursor: uuid|null }`;
  `AuditLogQuerySchema` coerces `limit` (rejects `>100`, defaults to 50) and validates `cursor` as
  a uuid.
- **API e2e (real Postgres, `test:coverage` / `RUN_E2E=1` + Docker):**
  - 200 for ADMIN; **403 for a non-admin** (mandatory per CLAUDE.md — the deny test, not just the
    allow test).
  - Filter application: `targetType`/`targetId`/`from`/`to` narrow the result set.
  - Actor resolution: a row by a real user carries `actorName`/`actorEmail`; a `retention.cleanup`
    row (actor `SYSTEM_ACTOR_ID`) carries `null`/`null`.
  - **Discriminating cursor test:** seed rows that **share a `timestamp`**, page with a small
    `limit`, and assert across the boundary that **no row is skipped or duplicated** and that
    `nextCursor` is `null` on the final page. This is the test that proves the keyset is correct
    against real Postgres.
- **Dashboard (unit, node-env vitest):** `audit-view` — `actorLabel` (System / name+email / UUID
  fallback), `formatDiff` (object, null), `buildAuditParams` (omits empties, includes cursor).

Green gate before done: `pnpm lint && pnpm typecheck && pnpm test && pnpm build`, plus the worker/api
e2e via the coverage gate (`RUN_E2E=1` + Docker). Coverage ≥80% on `apps/api` and
`packages/contracts` holds.

## 7. Constraints (binding, from CLAUDE.md)

- Prisma only in `admin.repository.ts` (both queries); controller/service stay Prisma-free.
- New endpoint shape: pipe scoped to the `@Query` param (already is); ADMIN `@Roles` gate already
  present; **the 403 test is required**.
- Zod-only validation; types inferred from schemas; Zod 4 top-level helpers.
- Never log `diff` contents at info level indiscriminately, and never `windowTitle`/screenshot
  bytes/secrets. (The audit `diff` can contain `time_entry`/`team` snapshots — do not add new
  logging of it.)
- Migration committed with the schema change in the same commit.
- Commits: Conventional Commits, scope ∈ {contracts, api, dashboard, db}, **no AI attribution**,
  author = repo git user.
