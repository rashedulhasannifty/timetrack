# Slice 2.4 — Idle & focus nudges (local) — design

**Date:** 2026-07-18
**Phase:** 2 (Monitoring + transparency)
**Roadmap:** `docs/plans/phase-2-monitoring.md` §Slice 2.4
**PRD:** §6.4 (idle/distraction), §6.1 (tracking), §4.3 (symmetric transparency), §11 (Phase 2 hard gate)

---

## 1. Goal

Deliver **local, transparent** desktop notifications on the macOS client, closing out slice 2.4:

1. **Idle nudge** — "Idle for X min — still working?" when the employee goes idle past the
   team threshold.
2. **Forgot-to-start reminder** — "You've been active N min without tracking — start?" when the
   employee is working with no time entry running (manual mode only).
3. **End-of-day summary shell** — a minimal "Today: ~Xh Ym tracked" notification at a fixed local
   hour.

**Client-only.** The idle-event persistence loop is already complete: `POST /v1/idle-events`
(ingest) + `GET /v1/idle-events` (self/manager read) exist, the `IdleEvent` model/contract exist,
and the client already enqueues + syncs `IdleEvent`s. The exit criterion says **nudges are local**
(no network dependency), so this slice touches **no** contracts, db, api, worker, or dashboard
code — only `apps/client-macos`.

## 2. Current state (verified against the code, 2026-07-18)

Already built (this slice does **not** rebuild any of it):

- **Idle detection + away resolution (slice 1.7c):** `Tracking/IdleMonitor.swift` (pure state
  machine: `inactive`/`active`/`away`/`awaiting`), fed by `Tracking/WorkspaceObserver.swift` (a
  15 s timer sampling `CGEventSource.secondsSinceLastEventType(.combinedSessionState, …)` — a
  **content-free seconds-since-last-input scalar**, no key/pointer content — plus `NSWorkspace`
  sleep and screen lock/unlock). `App/AutoTrackingCoordinator.swift` turns decisions into
  `TimeTracker` writes + `IdleEvent` enqueues and presents the keep/discard **window**
  (`UI/AwayResolutionView.swift`).
- **IdleEvent persistence + sync (slice 2026-07-14 + 2.1):** client enqueue (`IdleEventPayload`)
  - `SyncEngine` drain; `POST /v1/idle-events` (ingest, self-attributed) and `GET /v1/idle-events`
    (read, `@ResourceScope`); `IdleEvent` contract + Prisma model.
- **Tracking model:** `Tracking/TimeTracker.swift` — manual start/stop via the menu bar
  (`MenuViewModel.start()`/`stop()`); auto-start on activity via `AutoTrackingCoordinator` **only
  when `autoStartOnLogin=true`** (`AppDelegate.startAutoTrackingIfEnabled`). During a **manual**
  session the auto layer stands down entirely (`isManualSessionLive` short-circuits
  `tick`/`markAway`/`resume`). `TimeTracker` keeps **no** daily history — it holds only the current
  span state and enqueues completed spans fire-and-forget.
- **Capture gating:** screenshot + activity capture are gated behind `isTracking()`, so **no
  running entry ⇒ no monitoring at all**. `AckGate` (`Policy/AckGate.swift`) is the single gate
  between capture-adjacent code and activity sampling.

Missing — the real 2.4 work (all net-new on the client; **no** `UNUserNotification` /
`UserNotifications` code exists anywhere in `Sources` today):

- Local-notification infrastructure (authorization + fire + clear).
- The three nudges above and the pollers/hooks that trigger them.
- A local per-day tracked-time accumulator (the client retains none today).
- AppDelegate wiring + sign-out teardown for all of it.

## 3. Design overview

Everything lives in `apps/client-macos/Sources/TimeTrack`. Five isolated units, each with a
protocol seam and injected clock where relevant, matching the existing conventions (spy doubles,
deterministic `clock`/`idGen`):

```
Notifications/LocalNotifier.swift        UNUserNotification wrapper (protocol + concrete + spy-able)
Notifications/EndOfDayScheduler.swift    daily local-hour timer → summary notification
Tracking/ManualNudgeMonitor.swift        manual-mode poller → forgot-to-start + manual idle nudges
Tracking/DailyTotalAccumulator.swift     sums today's tracked seconds (local day)
  + IdleMonitor delegate hook (auto-mode idle nudge)
  + TimeTracker.onSpanClosed callback (feeds the accumulator)
  + AppDelegate wiring + sign-out teardown
```

**Mode split (mutually exclusive on the install-time `autoStartOnLogin` policy snapshot — the same
install-time-snapshot model the capture subsystems already use):**

| Config                            | Idle poller running            | Idle nudge source              | Forgot-to-start                 |
| --------------------------------- | ------------------------------ | ------------------------------ | ------------------------------- |
| `autoStartOnLogin=true` (auto)    | `WorkspaceObserver` (existing) | `IdleMonitor` active→away hook | — (activity auto-starts a span) |
| `autoStartOnLogin=false` (manual) | `ManualNudgeMonitor` (new)     | manual idle rule (notify-only) | forgot-to-start rule            |

Only **one** idle poller ever runs. The two modes never both install.

## 4. `Notifications/LocalNotifier` — the net-new infra

```swift
protocol LocalNotifying: AnyObject {
    func requestAuthorization()
    func notify(id: String, title: String, body: String)
    func clearAll()   // pending + delivered
}
```

- Concrete `UNUserNotifier` wraps `UNUserNotificationCenter.current()`:
  `requestAuthorization(options: [.alert, .sound])`; `notify` builds a
  `UNMutableNotificationContent` + an immediate (`nil`-trigger) `UNNotificationRequest`;
  `clearAll` calls `removeAllPendingNotificationRequests()` + `removeAllDeliveredNotifications()`.
- **Authorization** is requested **once at ready** (post-ack, on the `becomeReady` path) — an
  employee-facing prompt, consistent with §1 transparency (no hidden/silent mode).
- **Auth-denied ⇒ `notify()` silently no-ops** (the center drops unauthorized requests). This is a
  known, accepted shell state: the three nudges simply don't appear. Fail-safe; no fallback path.
- **Ethics:** employee-facing strings only, no sensitive data, **no network** (local
  `UNUserNotification` only). Nothing here logs.
- Tests inject a `SpyNotifier` recording `notify` calls; the concrete type is exercised only
  behind the protocol.

## 5. Idle nudge

### 5a. Auto mode — hook the existing `IdleMonitor`

Add **one** delegate method, fired **only** in the `tick` active→away branch
(`IdleMonitor.swift:68`, the genuine idle-threshold crossing), **not** in `markAway` (sleep/lock —
the screen is off/locked, so "still working?" would be unseen and wrong):

```swift
// IdleMonitorDelegate (new; default no-op via protocol extension so existing conformers/tests don't break)
func idleMonitorDidCrossIdleThreshold(_ monitor: IdleMonitor, afterSeconds seconds: Int)
```

`AutoTrackingCoordinator` implements it → `LocalNotifier.notify("Idle — still working?")`. The
state machine guarantees exactly one firing per active→away transition (one-shot per away span). In
auto mode the same crossing already auto-stops the clock, so the nudge is purely informational —
which is what was chosen.

**Non-breaking:** the new protocol method ships with a default empty implementation via a protocol
extension, so `AutoTrackingCoordinator` (the sole real conformer) and any test-fake delegates
compile unchanged; only the coordinator overrides it.

### 5b. Manual mode — `ManualNudgeMonitor` (notify-only)

When a **manual** entry is live and the user goes idle ≥ threshold, fire
"Idle Xm — still tracking?" — **notify-only, it never touches the clock** (respects the invariant
that the auto layer never auto-stops a manual entry; this monitor does not feed `IdleMonitor`, so
it produces no stop and no spurious `IdleEvent`). One-shot per idle stretch; the guard resets when
the user becomes active again or stops tracking.

**Documented boundary:** a manual Start _inside_ an `autoStartOnLogin=true` config gets **no**
manual idle nudge — the auto layer stands down and no `ManualNudgeMonitor` is installed in auto
mode. Rare; the anti-over-count value lands for manual-mode deployments, the realistic case. Full
coverage (manual sessions under either config) is an explicit future follow-up, not a silent gap.

## 6. Forgot-to-start reminder — `ManualNudgeMonitor` (manual mode only)

`Tracking/ManualNudgeMonitor` is one poller installed **only when `autoStartOnLogin=false`**, gated
behind `AckGate`, reading the **same content-free `CGEventSource` idle scalar** `WorkspaceObserver`
uses (≈15 s interval). It owns two mutually-exclusive-by-tracker-state notify-only rules:

- **Forgot-to-start** — `!isTracking` **and** continuously active (idle stayed below a small
  "recently active" bound) for ≥ **10 min** (a client constant `forgotToStartMinutes = 10`) →
  "You've been active 10 min without tracking — start?" One-shot per active stretch; resets when
  the user starts tracking or goes idle.
- **Manual idle** — a manual entry live **and** idle ≥ `idleThresholdMinutes` → §5b nudge.

Because `isTracking` partitions the two rules, one poller cleanly covers both without ever running
alongside `WorkspaceObserver`.

## 7. End-of-day summary shell

### 7a. `Tracking/DailyTotalAccumulator`

`TimeTracker` gains an **optional** callback (default `nil` → **no call-site breakage**, per the
shared-init-widening lesson):

```swift
var onSpanClosed: ((_ start: Date, _ end: Date) -> Void)?   // invoked in close() and recordSpan()
```

`DailyTotalAccumulator` consumes it: sums span durations into a running total keyed by the **local**
calendar day (injected `Calendar`/`clock`). **Midnight-crossing rule (explicit):** a span is
attributed **to its end-day**; when a span's end-day differs from the accumulator's current day, the
total rolls over (resets to that span's duration for the new day). Simple and total; no partial-day
splitting (a "shell").

### 7b. `Notifications/EndOfDayScheduler`

A daily wall-clock `Timer` scheduled for the next occurrence of a fixed local hour
(**`endOfDayHour = 18` / 18:00 local**, a client constant; injected clock/calendar for tests). On
fire: read the accumulator's today-total → `LocalNotifier.notify("Today: ~Xh Ym tracked. Nice
work.")` → reschedule for the next day.

**Best-effort limitation (stated, not worked around):** a wall-clock `Timer` won't fire if the app
isn't running or the Mac is asleep at 18:00. Acceptable for a shell; the summary is a nicety, not a
record of truth (the truth is the synced time entries).

## 8. AppDelegate wiring + sign-out teardown

- **Install at ready** (post-ack): construct `LocalNotifier`, request authorization once; attach
  `DailyTotalAccumulator` to `timeTracker.onSpanClosed`; install `EndOfDayScheduler`; and install
  **exactly one** of `WorkspaceObserver`-idle-nudge-hook (auto) or `ManualNudgeMonitor` (manual)
  per `autoStartOnLogin`. The `ManualNudgeMonitor`'s poll loop runs behind `AckGate`
  (`withCaptureAllowed`), same as every other activity reader.
- **Sign-out teardown** (extends `stopAutoTracking`): invalidate the `ManualNudgeMonitor` +
  `EndOfDayScheduler` timers, clear the accumulator, reset all one-shot guards, detach
  `onSpanClosed`, **and `LocalNotifier.clearAll()`** (pending + delivered) — otherwise the prior
  user's "Today: Xh" or a pending nudge leaks into the next user's session (the same
  cross-user-attribution class as the known sign-out prompt-window leak). This teardown is a
  first-class part of the slice, tested.

## 9. Testing (XCTest — `DEVELOPER_DIR` = Xcode, per the client test harness)

- **`LocalNotifier`:** through the protocol — `notify` forwards when authorized, no-ops when
  unauthorized (spy/fake center); `clearAll` clears pending + delivered.
- **Auto idle nudge:** a `tick` crossing the threshold (active→away) fires **one** nudge;
  `markAway` (sleep/lock) fires **none**; exactly one per away span. (Drive `IdleMonitor` +
  a spy `AutoTrackingCoordinator` delegate / spy notifier.)
- **`ManualNudgeMonitor`:** forgot-to-start fires at 10 min continuous active + `!tracking`, resets
  on start/idle, one-shot; manual idle nudge fires at threshold while a manual entry is live and
  **never stops the clock** (assert `TimeTracker` state unchanged); not installed / never fires in
  auto mode.
- **`DailyTotalAccumulator`:** sums same-day spans; a span whose end crosses local midnight
  attributes to the end-day and rolls the total over; injected clock/calendar make it deterministic.
- **`EndOfDayScheduler`:** fires at the configured local hour, reads the accumulator total,
  reschedules for the next day (injected clock).
- **Sign-out teardown:** timers invalidated, accumulator cleared, guards reset, `onSpanClosed`
  detached, `clearAll()` called — no state survives into a simulated next session.
- **No network** anywhere in the nudge paths (the exit criterion) — asserted structurally: the
  nudge units depend only on `LocalNotifying` + local state, never a URLSession/uploader.

## 10. Verification (DoD requires end-to-end, not just tests)

`swift build` + `swift test` green (`DEVELOPER_DIR` = Xcode). Then drive the real app:

1. **Idle nudge (auto):** run with `autoStartOnLogin=true`, let the machine sit idle past the
   threshold → observe the "still working?" notification as the clock auto-stops.
2. **Manual idle nudge + forgot-to-start (manual):** run with `autoStartOnLogin=false` → stay
   active without starting the clock past 10 min → forgot-to-start notification; then Start
   manually and go idle past threshold → "still tracking?" notification, and confirm the menu-bar
   clock **keeps running**.
3. **End-of-day:** temporarily point `endOfDayHour` at the next minute (or inject the clock) → the
   "Today: ~Xh Ym tracked" notification fires with a plausible total.
4. **Sign-out:** sign out with a pending/delivered nudge → confirm Notification Center is cleared
   and nothing re-appears for the next sign-in.
5. Paste real observations (no fabricated results).

## 11. Out of scope (explicit)

- **Distraction / focus alerts** beyond idle — Phase 3 (PRD §6.4).
- **Manual-session idle nudge under an `autoStartOnLogin=true` config** — the §5b boundary; a named
  follow-up, not this slice.
- **Server-configurable nudge durations / end-of-day hour** — client constants here (YAGNI; no
  TeamSettings/contracts/migration change).
- **A rich end-of-day summary window / breakdown** — a one-line notification "shell" only.
- Any change to `/idle-events`, the away-resolution window, `IdleEvent` sync, the dashboard, the
  API, or the worker.

## 12. Guardrails (apply here)

- **§1 transparency:** every new surface is an employee-facing **local** notification — no hidden or
  silent mode, no kill switch.
- **No keystroke content:** only the content-free idle-seconds scalar is read (identical to the
  existing `WorkspaceObserver`) — no key/pointer content, no event taps, no global monitors.
- **AckGate not bypassed:** the manual-mode poller runs behind `AckGate`, the same gate every other
  activity reader uses; no capture-adjacent path is opened outside it.
- **No network for nudges** (exit criterion) — local notifications only.
- **Nothing sensitive logged;** no new dependency (`UserNotifications` is a system framework).
- **Non-breaking core edits:** `TimeTracker.onSpanClosed` optional/default `nil`; the new
  `IdleMonitorDelegate` method defaulted via protocol extension.

## Done when

An employee running the client sees: an idle "still working?/still tracking?" notification when
they go idle past the threshold (auto **and** manual per §5), a "forgot to start" reminder when
active without tracking in manual mode, and a minimal end-of-day "Today: ~Xh tracked" notification —
all **local**, all transparent, none touching the network — with sign-out fully clearing notifier
state; demonstrated end-to-end with `swift build`/`swift test` green.
