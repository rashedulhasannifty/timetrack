# Slice 4.5 — Advanced admin controls — Design

**Date:** 2026-07-24
**Roadmap:** `docs/plans/phase-4-sso-admin.md` Slice 4.5. **PRD:** §6.6.

## Context

Most of the roadmap's 4.5 bullets already ship:

- **Per-team policy editor** — `PATCH /admin/settings` (ADMIN-only, audited) + dashboard
  `admin/settings/SettingsForm.tsx` already edits all 11 policy fields.
- **App list management** — `productiveApps`/`unproductiveApps` are part of that same form.

What remains: **separate site lists** and **role management**. Two independent features.

## Feature A — Separate productive/unproductive sites

Today the macOS client resolves the front browser's host (`SiteResolver`) but the
`Categorizer` matches that host against `productiveApps`/`unproductiveApps` — apps and sites
share one list. Split them into their own lists.

- **Contracts** (`team-settings.ts`): add `productiveSites: string[]` and
  `unproductiveSites: string[]` to the **default-free** `teamSettingsFields`. They flow into
  `TeamSettingsSchema` with `.default([])` and, via `TeamSettingsFieldsSchema.partial()`,
  into `UpdateSettingsSchema` automatically. No partial-defaults landmine — the partial is
  built from the default-free base.
- **DB:** none. `Team.settings` is a Zod-on-read JSON column; absent keys default on read.
- **API:** none beyond contracts. `PATCH /admin/settings` already validates via the partial
  schema and writes an `AuditLog` row on every change.
- **Dashboard** (`SettingsForm.tsx`): two more list editors mirroring the app-list UI.
- **Client (Swift):**
  - `Categorizer` takes four lists. **Host matches only sites; app name matches only apps.**
    UNPRODUCTIVE still wins on overlap; case-insensitive; dotted-suffix host match retained.
  - `PolicyClient.EffectivePolicy.Settings` decodes `productiveSites`/`unproductiveSites`
    (`decodeIfPresent ?? []`), added to `CodingKeys` and to the memberwise init with `= []`
    defaults so existing call sites/tests don't break (single executable target).
  - Update the `AppDelegate` `Categorizer(...)` construction in the SAME change.
  - Update `CategorizerTests` + `PolicySettingsDecodeTests`.
- **Behavior note (clean split):** an existing `"youtube.com"` sitting in _unproductiveApps_
  will stop categorizing the site once host-matching moves to _unproductiveSites_.
  Acceptable — pre-launch, no production `Team.settings` to migrate. Called out here.

## Feature B — Role management

- **Contracts** (`users.ts`): `UpdateUserSchema` becomes `{ deactivated?: boolean, role?: Role }`
  with a refine requiring at least one field present (today it is `{ deactivated }` required).
- **API** (`users.service.update` + `users.repository`): apply a role change with guardrails
  mirroring the existing deactivate rules:
  - **same-team only** (already enforced for the user mutation).
  - **no self-demotion** — an admin cannot drop their own `ADMIN` role (self-lockout),
    mirroring the existing no-self-deactivation rule → 403.
  - **last-active-admin guard** — demoting the last active `ADMIN` to a lower role → 409,
    reusing the repository's existing `LAST_ADMIN` sentinel pattern.
  - **audit** — write an `AuditLog` row on a role change (4.5 requires audit-on-every-change).
- **Dashboard** (`admin/users/page.tsx`): a per-user role control (server action →
  `api.updateUser`) with the same 409/guard messaging as deactivate.

## Testing

- **API unit:** role change happy path; last-admin demotion → 409; self-demotion → 403;
  cross-team → 403; audit row written; `UpdateUserSchema` rejects an empty body; site fields
  validate through the pipe. Write the 403/409 tests, not just the 200.
- **Client (Swift):** `CategorizerTests` — host matches sites (not apps) and app name matches
  apps (not sites); overlap → UNPRODUCTIVE. `PolicySettingsDecodeTests` — new keys decode and
  default to `[]` when absent.
- **Dashboard:** settings form round-trips the site lists; the role action calls the API.

## Out of scope

Per-team IdP config; SCIM/deprovisioning; bulk role edits; site categorization for
non-browser apps; migrating existing app-list entries into site lists.
