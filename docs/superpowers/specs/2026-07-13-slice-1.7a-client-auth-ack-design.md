# Slice 1.7a — Client auth + policy + ack gate — Design

**Date:** 2026-07-13
**Plan reference:** `docs/plans/phase-1-mvp.md` § "Slice 1.7 — macOS client MVP" → sub-slice **1.7a**
**PRD:** §4.1 (ack gate — no capture before acknowledgement), §6.8 (auth: email/password, short-lived access JWT + rotating refresh), §7.6 (tokens never in JS / stored securely)
**Non-negotiables (CLAUDE.md §1 / ROADMAP §2):** the ack gate is the single structural gate; no bypass, no admin override, no stealth; the menu-bar indicator is always visible; a user acknowledges **their own** monitoring only.

## Goal

Give the macOS client a real identity and the ack gate real inputs: an employee signs in
(email/password), tokens are stored in the macOS Keychain, the access token refreshes on
expiry / 401, and — before any capture path may run — the client fetches the effective
policy and, while `ackRequired`, presents the acknowledgement screen. Accepting calls
`POST /users/:id/ack-monitoring`; only then does `AckGate.withCaptureAllowed` open.

This slice proves **auth + gate** only. No capture services are constructed yet (menu
tracking is 1.7b, auto-detection 1.7c, offline buffer/sync 1.7d). The gate stays closed by
construction because nothing behind it is built.

## Scope

One branch (`slice-1.7a-client-auth-ack`), three logical commits:

1. **Auth core** — token storage, auth networking, session actor, JWT decode, and their unit tests (adds the XCTest target).
2. **Gate wiring** — `PolicyProviding` protocol, async token provider + 401-retry in `PolicyClient`, `AckGate` re-pointed at the protocol, the acknowledge call, and the gate test.
3. **UI + app wiring** — login window, acknowledgement window, `AppDelegate` bootstrap flow.

**Decisions (confirmed):** login is a **dedicated `NSWindow`** presented on launch when
unauthenticated (standard for an `LSUIElement` menu-bar app). The test target
**`@testable import`s the existing executable target** (`TimeTrack`); no library extraction.

**Out of scope:** any capture (screenshot / activity / idle), menu-bar Start/Stop/project
picker (1.7b), the GRDB offline buffer and `SyncEngine` (1.7d). **No new SwiftPM dependency** —
Keychain uses the system `Security` framework; GRDB is deferred to 1.7d.

## Commit 1 — Auth core

All new files under `Sources/TimeTrack/Auth/`. Every collaborator the session depends on is
behind a protocol so `AuthSession` is testable without the network or the Keychain.

### `TokenStore.swift` — the refresh token at rest

```swift
/// Persists only the long-lived secret (the refresh token). The access token is short-lived
/// and lives in memory on AuthSession, re-minted via refresh.
protocol TokenStore {
    func readRefreshToken() -> String?
    func saveRefreshToken(_ token: String)
    func clear()
}

/// Prod impl over the system Security framework (kSecClassGenericPassword,
/// service "com.timetrack.client", account "refreshToken"). No new dependency.
final class KeychainTokenStore: TokenStore { /* SecItemCopyMatching / SecItemAdd / SecItemDelete */ }
```

A test-only `InMemoryTokenStore` lives in the test target (not shipped).

### `JWTDecoder.swift` — read our own `sub`

```swift
/// Decodes the payload segment of a JWT (base64url) into the claims the client needs.
/// No signature verification — the API verifies; the client only needs its own user id
/// for the ack-monitoring call. Mirrors JwtClaimsSchema { sub, role, teamId }.
enum JWTDecoder {
    struct Claims: Decodable { let sub: String; let role: String; let teamId: String }
    static func claims(from accessToken: String) throws -> Claims
}
```

### `AuthClient.swift` — login / refresh networking

```swift
/// Mirrors LoginSchema / RefreshSchema / TokenPairSchema in @timetrack/contracts.
struct TokenPair: Decodable { let accessToken: String; let refreshToken: String; let expiresIn: Int }

enum AuthError: Error { case invalidCredentials; case refreshRejected; case transport(Error); case server(Int) }

protocol AuthClienting {
    func login(email: String, password: String) async throws -> TokenPair
    func refresh(refreshToken: String) async throws -> TokenPair
}

final class AuthClient: AuthClienting {
    init(baseURL: URL)               // POST {baseURL}/auth/login, /auth/refresh
}
```

401 on login → `.invalidCredentials`; 401 on refresh → `.refreshRejected`; other non-2xx →
`.server(status)`. All routes are under `/v1` (baseURL already carries it — see wiring).

### `AuthSession.swift` — the identity, serialized

```swift
/// The single owner of the client's tokens. An actor so concurrent accessToken() callers
/// (e.g. several requests after expiry) share ONE refresh instead of racing.
actor AuthSession {
    init(client: AuthClienting, store: TokenStore)

    var isAuthenticated: Bool { get }        // has a usable refresh token
    var userId: String? { get }              // decoded from the current access token's sub

    /// On launch: if the store has a refresh token, refresh once to mint an access token.
    /// Returns whether we ended up authenticated. Never throws to the caller for a rejected
    /// refresh — it clears and returns false (→ show login).
    func bootstrap() async -> Bool

    func login(email: String, password: String) async throws   // persists refresh token, keeps access in memory
    func logout()                                                // clear() + drop in-memory access

    /// Returns a valid access token, refreshing if expired/near-expiry. Throws if there is
    /// no session or the refresh is rejected (caller routes to login).
    func accessToken() async throws -> String
}
```

Expiry: store `expiresIn` as an absolute deadline at mint time; `accessToken()` refreshes when
within a small skew (e.g. 30 s) of the deadline. `Date` is real here (client runtime), not the
workflow sandbox.

### Tests (new XCTest target — `Package.swift`)

Add:

```swift
.testTarget(name: "TimeTrackTests", dependencies: ["TimeTrack"], path: "Tests/TimeTrackTests")
```

with `@testable import TimeTrack`. Test files:

- `JWTDecoderTests` — a hand-built `header.payload.signature` with a known `sub` decodes to it; a malformed token throws.
- `AuthSessionTests` (fakes for `AuthClienting` + `TokenStore`): `bootstrap()` with a stored refresh token mints an access token and reports authenticated; with none, reports unauthenticated. `login()` persists the refresh token to the store. A refresh that throws `.refreshRejected` during `bootstrap()` clears the store and reports unauthenticated. `logout()` clears the store.

## Commit 2 — Gate wiring

### `PolicyProviding` protocol + `PolicyClient` (edit `Policy/PolicyClient.swift`)

```swift
protocol PolicyProviding {
    func effectivePolicy() async throws -> EffectivePolicy
}

final class PolicyClient: PolicyProviding {
    init(baseURL: URL, session: AuthSession)     // was: accessToken: () -> String?
    // GET {baseURL}/policy/effective with Bearer session.accessToken().
    // On 401: ask the session to refresh (retry accessToken()) and retry the request ONCE;
    // a second 401 throws → AckGate surfaces .policyUnavailable (gate stays closed, fail-safe).
}
```

`EffectivePolicy` is unchanged. The token provider becomes the async `AuthSession`, which is
what makes refresh-on-401 possible.

### `AckGate` (edit `Policy/AckGate.swift`)

Change the dependency from concrete `PolicyClient` to `PolicyProviding`:

```swift
final class AckGate {
    init(policyProvider: PolicyProviding)        // was: policyClient: PolicyClient
    // body unchanged: fetch policy; guard !ackRequired else throw .notAcknowledged; run body.
}
```

This is the change that makes the mandated gate test possible — the test injects a fake
`PolicyProviding`. **No runtime `if` is added; the structural gate is preserved verbatim.**

### `AckClient.swift` (new, `Policy/`)

```swift
/// Records the signed-in user's acknowledgement. The id is the user's OWN sub (from the
/// access token) — the client cannot ack for anyone else (server enforces self-only too).
final class AckClient {
    init(baseURL: URL, session: AuthSession)
    func acknowledge(userId: String) async throws   // POST {baseURL}/users/{userId}/ack-monitoring
}
```

### Test

- `AckGateTests` (`FakePolicyProvider`): `ackRequired == true` → `withCaptureAllowed { ran = true }` **throws `AckGateError.notAcknowledged` and `ran` stays false** (capture body never runs). `ackRequired == false` → the body runs and its value returns. A provider that throws → `withCaptureAllowed` propagates (gate closed on policy failure).

## Commit 3 — UI + app wiring

### Login (`Auth/LoginView.swift` + a window controller)

A SwiftUI `LoginView` (email, password, submit, inline error label) hosted in a dedicated
`NSWindow` via a small `LoginWindowController`. Submit → `AuthSession.login`; on
`.invalidCredentials` show "Incorrect email or password" and stay; on success, close the
window and hand back to the launch flow. The app activates (`NSApp.activate`) so the window
is focused despite `LSUIElement`.

### Acknowledgement (`Policy/AckView.swift` + window controller)

SwiftUI `AckView` renders `policy.policyText` and `policy.policyVersion` with an
**"I acknowledge"** button (and a visible statement that monitoring will run — never hidden).
Accept → `AckClient.acknowledge(userId:)` → re-fetch `effectivePolicy()`; when `ackRequired`
flips false, close the window and mark the client ready. No "skip"/"later" that starts
capture — declining simply leaves the gate closed.

### `AppDelegate` wiring (edit `App/AppDelegate.swift`)

Replace the `TODO(scaffold)` with the launch flow (all off the main actor where async):

1. `statusItem.install()` (indicator always visible, unchanged).
2. Construct `KeychainTokenStore`, `AuthClient`, `AuthSession`, `PolicyClient`, `AckGate`, `AckClient` from the base URL (`/v1`) — read from an env/Info.plist value with a localhost dev default; **no secret** in the client.
3. `await session.bootstrap()`. If not authenticated → present the login window; after login, continue.
4. Fetch `effectivePolicy()`. If `ackRequired` → present the ack window; after acknowledgement, continue.
5. Ready state: the `AckGate` is constructed and available for 1.7b+ capture paths. **No capture is started in 1.7a.** On policy-fetch failure, surface a retry (the gate reports `.policyUnavailable` and stays closed).

### Base URL / configuration

The API base URL (including `/v1`) comes from an `Info.plist` key (e.g. `TimeTrackAPIBaseURL`)
defaulting to `http://127.0.0.1:3001/v1` for dev (API `API_PORT` default is 3001). No credentials or secrets ship in the client
(CLAUDE.md §6 / PRD §7.6).

## Data flow

```
launch
  └─ AuthSession.bootstrap()
        ├─ no stored refresh token ─────────────► LoginWindow ─ login() ─┐
        └─ stored token → refresh() → access ────────────────────────────┤
                                                                          ▼
                                              PolicyClient.effectivePolicy()  (Bearer, retry-on-401)
                                                                          │
                                            ackRequired? ── yes ──► AckWindow ─ AckClient.acknowledge(sub)
                                                 │                        └─ re-fetch policy ─┐
                                                 └── no ───────────────────────────────────────┤
                                                                                                ▼
                                                              ready — AckGate available to capture (1.7b+)
```

Every future capture path (1.7b–d) calls `AckGate.withCaptureAllowed`, which re-checks
`ackRequired` live on each use — acknowledgement is not cached past the policy response.

## Error handling

| Condition                             | Behavior                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------- |
| Bad credentials (login 401)           | Inline "incorrect email or password"; stay on login form                  |
| Refresh rejected (expired/revoked)    | `AuthSession` clears the store; flow returns to the login window          |
| Policy fetch fails (network / 2× 401) | `AckGate` throws `.policyUnavailable`; gate stays closed; UI offers retry |
| Ack POST fails                        | Surface error on the ack window; gate stays closed; user can retry        |

Fail-safe throughout: any uncertainty about policy state leaves the gate **closed**.

## Testing summary (XCTest, `Tests/TimeTrackTests`)

- `JWTDecoderTests` — decodes `sub`; rejects malformed tokens.
- `AuthSessionTests` — bootstrap (stored / none / rejected), login persists, logout clears — via fakes.
- `AckGateTests` — capture refused while `ackRequired`; allowed when not; closed on policy error.

Run with `swift test` from `apps/client-macos`. (Client tests are outside the pnpm gate; run
explicitly.)
