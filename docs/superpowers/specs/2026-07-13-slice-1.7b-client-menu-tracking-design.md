## 1. Goal & scope

A signed-in employee who has acknowledged the monitoring policy can track time manually
from the menu bar: pick a project/task, Start, Pause/Resume, Stop. Each completed span is
written to a local buffer keyed by a client-minted UUIDv7. The always-visible menu-bar
indicator reflects idle vs tracking.

**In scope**

- Menu-bar dropdown UI: start/stop/pause, searchable project→task picker, "My Data",
  "Settings", "Quit".
- Status-item icon reflecting `idle` / `tracking`.
- `TimeTracker`: manual lifecycle minting UUIDv7 `TimeEntry` records into `BufferStore`.
- `GET /v1/projects` fetch (with tasks) for the picker, plus an offline cache.
- Gating: manual tracking is enabled by the launch ack flow + a local ready flag — **not**
  by `AckGate.withCaptureAllowed`.

**Out of scope (later slices / phases)**

- Automatic tracking — active-app / idle detection (1.7c).
- The actual sync drain / `POST /time-entries` (1.7d). 1.7b only **enqueues** to the buffer.
- The real "My Data" employee self-view screen (Phase 2, §4.3). In 1.7b the row opens the
  dashboard in the browser.
- Per-entry note UI (deferred; the buffered payload carries `note: null`).
- Screenshot capture, the "Capturing" icon state, and the screenshot disclosure line
  (Phase 2).

## 2. Constraints (carried from 1.7a + CLAUDE.md/PRD)

- **No new SwiftPM dependency.** UUIDv7 is hand-rolled; the offline cache uses Foundation
  `JSONEncoder` + a file in Application Support. (CLAUDE.md §2)
- **The ack gate stays the single structural gate for _capture_.** Manual time tracking is
  the employee's own action and is **not** a capture path, so it does not route through
  `AckGate.withCaptureAllowed`. `AckGate` is untouched and reserved for the real capture
  paths in 1.7c+. No bypass, no admin override, no debug flag is added to it. (CLAUDE.md §1,
  PRD §4.1)
- **The menu-bar indicator is always visible; no stealth, no kill switch.**
  `StatusItemController.install()` stays; the icon only ever reflects idle/tracking.
  (CLAUDE.md §1, PRD §4.2)
- **All API routes are under `/v1`** (the injected base URL already carries it). Never break
  `/v1`. (CLAUDE.md §4)
- **No secret ships in the client.** The dashboard URL for "My Data" is derived from the
  configured API base URL (or its own `Info.plist` key), not hard-coded credentials.
- **Commits:** Conventional Commits, scope `client`, no AI attribution. (CLAUDE.md §0)
- **Tests reach the module via `@testable import TimeTrack`** (the pattern established in
  1.7a). Client tests run via `swift test` from `apps/client-macos`, outside `pnpm test`.

## 3. Architecture

The slice keeps the 1.7a shape: small units behind protocols, a thin `AppDelegate` that
wires them, and UI kept out of the logic. The one new seam is a `MenuViewModel` — the single
`ObservableObject` the SwiftUI dropdown observes, so the popover has no logic of its own and
`TimeTracker` has no UI of its own.

```
┌────────────┐     intents      ┌───────────────┐   start/stop/pause/resume   ┌─────────────┐
│ MenuBarView│ ───────────────▶ │ MenuViewModel │ ──────────────────────────▶ │ TimeTracker │
│  (SwiftUI) │ ◀─ @Published ── │  (@MainActor) │ ◀── state ────────────────  │             │
└────────────┘                  └───────┬───────┘                             └──────┬──────┘
      ▲ hosted in NSPopover             │ isReady (set by AppDelegate)               │ enqueue
      │                                 │ projects (from ProjectClient/Cache)        ▼
┌────────────────────┐                  │                                     ┌─────────────┐
│ StatusItemController│ ◀── icon state ─┘                                     │ BufferStore │
│  (NSStatusItem)     │                                                       │ (existing)  │
└────────────────────┘                                                        └─────────────┘
```

`AppDelegate` (from 1.7a) already resolves auth → policy → ack. When it reaches the ready
state (`!ackRequired`, or ack just completed) it flips `MenuViewModel.isReady = true` and
kicks off a project fetch. On policy failure the flag stays false, Start is inert, and the
existing `showPolicyUnavailable()` tooltip is shown.

## 4. Data flow & the tracking state machine

`TimeTracker` owns the entry lifecycle. Its injected `clock` and `idGen` make start/end
timestamps and the minted id deterministic under test.

State: `idle` → `tracking(entryId, startTime, selection)` → (`paused(selection)` | `idle`).

- **`start(projectId:taskId:)`** — `let now = clock(); let id = idGen(now)`; record
  `startTime = now`; state `.tracking`.
- **`stop()`** — `endTime = clock()`; build the `CreateTimeEntry` payload; `BufferStore.enqueue`;
  state `.idle` (selection cleared).
- **`pause()`** — identical close (endTime, enqueue) **but** state `.paused(selection)` —
  the selection is retained so Resume is one click. Paused time is excluded from any entry.
- **`resume()`** — `start` again with the retained selection → a **new** UUIDv7, a new
  contiguous span. (Pause = close + reopen; the data model stays one `startTime`/`endTime`
  per entry.)

**Buffered payload** — JSON matching `CreateTimeEntrySchema`:

```json
{
  "id": "<uuidv7>",
  "projectId": "<uuid|null>",
  "taskId": "<uuid|null>",
  "startTime": "<iso8601>",
  "endTime": "<iso8601>",
  "source": "MANUAL",
  "note": null
}
```

Only completed entries are enqueued (endTime known). Crash-durability of an in-progress
entry is a 1.7d concern (it lands with the buffer/sync work); 1.7b's offline guarantee is
that completed entries accumulate in the buffer while the backend is unreachable.

### Gating mechanism (the load-bearing decision)

Manual tracking must work offline for ≥24h. `AckGate.withCaptureAllowed` performs a **live
network policy fetch on every call**, so routing manual Start through it would break offline
tracking — and manual time logging touches no monitoring/hardware API, so by the letter of
the architecture it is not a capture path. Therefore:

- `MenuViewModel.isReady` starts `false`. The status item installs immediately (always
  visible). The **Start action is disabled** with the subtitle _"Acknowledge policy to
  begin"_ until ready.
- When `AppDelegate.proceedToPolicy()` confirms `!ackRequired` (or the ack window completes),
  it sets `isReady = true`.
- A small persisted marker (`UserDefaults`, key `ackedPolicyVersion:<userId>`, written on a
  confirmed ack, cleared on logout) lets an **offline relaunch** re-enable manual tracking
  without a live fetch. This marker gates **manual tracking only** — it never opens a capture
  path. Capture stays behind `AckGate`.
- `MenuViewModel.start()` no-ops when `!isReady` — a testable guard.

`AckGate` is not modified. The invariant "the single structural gate guards all capture"
holds; manual time logging simply isn't capture.

### Project picker & offline behavior

- On ready, `AppDelegate` triggers `ProjectClient.list()` → `GET /v1/projects` (returns
  projects with nested tasks in one query; available to any authenticated user, team-scoped
  server-side). Results populate `MenuViewModel.projects` and are written to `ProjectCache`.
- On launch (and before the fetch returns, or if it fails), the picker shows the cached
  projects so selection works offline. A successful fetch refreshes both the list and the
  cache.
- The picker filters project+task names client-side against the search field.

## 5. Menu-bar UI (against the design bundle)

The design lives in `design files/timetrack-design-system-mac-os-client` (dropdown = mockup
§2) with tokens in `design files/timetrack-design-system-token/project/TimeTrackTokens.swift`.
Recreate the visual output in SwiftUI; do not copy the HTML structure.

**Tokens:** copy `TimeTrackTokens.swift` into `Sources/TimeTrack/UI/`. Consume `TT.Palette`,
`TT.Radius`, `TT.Space`, and the `Font.tt*` scale (numeric styles carry `.monospacedDigit()`).

**Popover:** 340pt wide, material/blur background, 12pt radius (`TT.Radius.lg`-ish), hosted in
an `NSPopover` toggled from the status item.

- **Tracking state** — header `● Recording` (accent dot, pulsing) + clock glyph; large elapsed
  timer `HH:MM:SS` (34pt, weight 300, monospaced digits); subtitle
  `Since <start> · Project › Task`; buttons **Pause** (fill) + **Stop** (accent).
- **Idle state** _(inferred — the mockup only draws the tracking state)_ — header
  `Idle · Not tracking`; a single primary **Start** button (accent), disabled with
  _"Acknowledge policy to begin"_ until `isReady`.
- **Project picker** — "Switch project" label; search field with magnifier icon; scrollable
  project→task list (~132pt max); accent checkmark on the selected row.
- **Footer** — **My Data** link (opens the dashboard URL in the default browser) · **Settings…**
  (server URL + Sign out) · version string. **Quit** available (menu row or Settings).

**Deviations from the mockup (all matching approved decisions):**

1. **Note field** — the mockup has an "Add a note (optional)" input; note is deferred, so
   1.7b omits that row.
2. **Screenshot disclosure + "Capturing" icon state** — Phase 2; omitted (no screenshots in
   Phase 1).
3. **Recording color** — the token file defines a teal `recording` color, but dropdown mockup
   §2 uses **accent blue** for the recording dot/timer. Follow the mockup (the explicit
   primary design); reconcile the token later.

## 6. Testing

**XCTest (unit) — via `@testable import TimeTrack`, `swift test` from `apps/client-macos`:**

- `UUIDv7Tests` — version nibble is `0x7`; variant bits are `0b10`; the 48-bit timestamp
  prefix matches the injected `now`; output parses as a valid `UUID`; two mints are unique.
- `TimeTrackerTests` — `start` mints the id and records `startTime` from the injected clock;
  `stop` enqueues exactly one `CreateTimeEntry` with the right fields (`source: MANUAL`,
  `endTime` set, `note: null`), state returns to `.idle`; `pause` enqueues and retains the
  selection; `resume` opens a **new** id with the same project; the enqueued JSON decodes to
  the expected shape. Uses a fake clock + fake `idGen` + a `BufferStore` spy.
- `MenuViewModelTests` — `start()` is a no-op while `!isReady`; flipping `isReady` enables it;
  selecting a project updates `selection`; state changes drive the expected icon state.

**Build-verified + manual smoke (like 1.7a's UI):** `ProjectClient` (network),
`ProjectCache` (a round-trip encode/decode test is cheap and worth adding),
`StatusItemController` popover, `MenuBarView`.

**Manual smoke (end-to-end):** infra + API up, seeded user who has acknowledged →
sign in → ack → open the dropdown → pick a project → **Start** (icon flips to tracking) →
**Pause** → **Resume** → **Stop** → confirm the buffer holds the expected entries (log) →
**My Data** opens the dashboard. Then kill the API and confirm tracking still starts/stops
(offline). Record the result; do not fabricate.
