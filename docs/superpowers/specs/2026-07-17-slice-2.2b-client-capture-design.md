# Slice 2.2b — Client screenshot capture — design

**Date:** 2026-07-17
**Phase:** 2 (Monitoring + transparency)
**Roadmap:** `docs/plans/phase-2-monitoring.md` §Slice 2.2
**PRD:** §6.2 (screenshot capture), §7.4 (screenshot pipeline), §4.1 (ack gate), §4.3 (symmetric transparency), §11 (Phase 2 gate)
**Depends on:** 2.2a (server pipeline) — merged. Fixed server contract, consumed as-is.

---

## 1. Goal & boundary

Ship the **client half** of the screenshot pipeline: the macOS client, while an employee is
tracking time, periodically grabs the screen via **ScreenCaptureKit** (behind `AckGate`),
persists the image to a durable binary buffer, and uploads it to `POST /screenshots` —
deleting the local file **only after a confirmed 201**.

This is Swift-only. No API change (the server already serves everything needed — verified
§3), no dashboard (that is 2.2c). Slice 2.2 is decomposed as in the 2.2a spec: **2.2a**
server pipeline (done) · **2.2b** client capture (this spec) · **2.2c** dashboard grid +
redact button.

**Cadence decision (product call — PRD §6.2 is silent on it):** capture runs **only while a
time entry is active** (manual or auto). Stopping the clock (lunch, end of day) stops
screenshots. This is the reading consistent with the PRD's trust-forward posture (§6.4
"real-time snitching destroys trust"); screenshotting a stopped clock is exactly what this
product avoids.

**Screen Recording permission decision (product call):** if macOS Screen Recording
permission is missing or revoked while screenshots are enabled and the employee is tracking,
the client **surfaces a visible menu-bar warning** ("Screen Recording permission needed" +
open System Settings) and **keeps tracking time normally**; capture resumes automatically
once permission is granted. Never silent (no hidden mode — CLAUDE.md §1); never blocks the
clock (capture permission and time tracking are independent concerns).

**Done when:** while tracking, a real screen grab is captured on the policy interval, streamed
to `POST /screenshots`, and the local file is deleted only after the 201; an offline capture
survives a restart and uploads on reconnect; a denied Screen Recording permission shows a
menu-bar warning without stopping the clock; sign-out clears the image buffer (cross-user
integrity). Verified end-to-end against the running API, plus the XCTest suite green.

## 2. Client capture is raw — the client does not blur

Blur / thumbnail-only is applied **server-side** by the 2.2a worker per
`TeamSettings.screenshotBlur`. The client captures and uploads the **raw** image, full stop.
The existing `ScreenshotCapturer` stub's comment "Respect the team blur setting" is now
**stale and must be removed** — re-adding client-side blur would duplicate server logic and,
for `BLUR`/`THUMBNAIL_ONLY`, could leave an unblurred raw the server intends never to retain.

## 3. Current state (verified against the code, 2026-07-17)

Reused, not rebuilt:

- **`AckGate.withCaptureAllowed`** (`Policy/AckGate.swift`) — the single structural gate for
  every capture path; fetches effective policy and throws if `ackRequired`. No override.
- **`UploadResult` + `classify`** (`Sync/TimeEntryUploader.swift`): 200/201→`success`,
  401→`authFailed`, 408/429/5xx→`transient`, other 4xx→`permanent(status)`. The 401→
  refresh-once→retry orchestration pattern.
- **`BackoffPolicy`** (`Sync/BackoffPolicy.swift`), **`AuthSession`** (`accessToken()`,
  `forceRefresh()`, `userId()`, `logout()`), **`UUIDv7.generate(now:)`**.
- **JSON `BufferStore` + `SyncEngine`** — the _pattern_ to mirror (atomic file-per-record,
  FIFO filename, drain-remove-on-2xx, prune stale). **Not reused directly** — it is
  JSON-per-record; screenshots are binary (2.2a §13).
- **`PolicyClient` / `EffectivePolicy.Settings`** — currently decodes only
  `idleThresholdMinutes` + `autoStartOnLogin`.
- **`AppDelegate`** — shows exactly where a capture path is installed (online `!ackRequired`
  branch, behind `AckGate`, like `startAutoTrackingIfEnabled`) and the sign-out cross-user
  teardown (`flushAndClearBuffer`, `stopAutoTracking`). Menu-bar warning surface exists
  (`statusItem.showPolicyUnavailable()`).
- **`ScreenshotCapturer.swift`** — a stub to repurpose/replace.

Verified server-side (no server work in this slice):

- `POST /screenshots` (multipart) and `GET /screenshots` live in 2.2a. Upload contract:
  text fields **`id` then `timestamp` first, file part last**; `userId` from the session
  token (never a body field); idempotent upsert on `id`; 201 on success; 10 MB / one-file /
  `image/png`+`image/jpeg` limits.
- `/policy/effective` returns the **full** `TeamSettingsSchema` as `settings`, which already
  includes `screenshotsEnabled` (bool) and `screenshotIntervalMinutes` (int, 5–60). The
  client only needs to decode these two extra keys.

## 4. New dependencies

**None.** ScreenCaptureKit is a system framework (link it in the executable target; the
package already targets macOS 14). No SwiftPM package added. Durability is hand-rolled
(no SQLite — CLAUDE.md §2), mirroring `BufferStore`.

## 5. Components

All new files under `Sources/TimeTrack/Capture/` unless noted.

### 5.1 `DisplayGrabbing` (protocol seam) — `Capture/DisplayGrabber.swift`

```swift
protocol DisplayGrabbing {
    /// Grab the main display and return encoded JPEG bytes. Throws on failure
    /// (no permission, no display, encode failure).
    func grab() async throws -> Data
}
```

Real impl `ScreenCaptureKitGrabber`:

- Captures the **main display only** (multi-display deferred — §10). Uses
  `SCShareableContent` → `SCScreenshotManager` / `SCStream` single-frame capture.
- Encodes **JPEG** (`~0.6` quality): comfortably under the server's 10 MB cap, where a retina
  PNG can exceed it. JPEG is the raw the manager/employee later views full-res; the server
  derives the thumbnail.
- This is the **only** component that needs a real display + TCC permission and cannot run in
  CI — hence the protocol seam so the whole pipeline around it is faked in tests (mirrors how
  the codebase unit-tests `classify` and build-verifies the async grab glue).

### 5.2 `ImageBufferStore` — `Storage/ImageBufferStore.swift`

Separate durable **binary** buffer (2.2a §13 — the JSON `BufferStore` is not reused).
Same durability model as `BufferStore`: one file per image under Application Support, atomic
`write-tmp-then-rename`, startup sweep of `.tmp-*`.

- Directory: `~/Library/Application Support/TimeTrack/screenshots/`.
- Filename: `<capturedAtMillis>__<uuidv7>.jpg`. The name carries FIFO order
  (`capturedAtMillis`), identity (`uuidv7` = the server `id`), **and the capture timestamp**
  without reading the file.
- **`capturedAtMillis` is the capture time = half the server PK `[id, timestamp]` and the
  partition key.** It is stamped at grab time and reused **verbatim** on every upload retry
  (derived from the filename → ISO 8601). Never regenerated at upload time — a retry across a
  month boundary must land on the same partition/PK, and the server upsert is idempotent only
  on the same `(id, timestamp)`.
- API: `enqueue(id:capturedAt:jpeg:)`, `take(limit:) -> [(id, capturedAt, url)]`,
  `remove(id:)`, `prune(olderThan:maxCount:)`, `clear()`.
- **Bounding:** images are far larger than JSON records, so prune is both age- **and**
  count-bounded (e.g. drop older than 7 days, and keep at most N newest) so a long offline
  stretch can't fill the disk. Dropped-record counts are logged, never silently discarded.

### 5.3 `ScreenshotUploader` — `Capture/ScreenshotUploader.swift`

Hand-built `multipart/form-data` POST to `<baseURL>/screenshots`.

- **Field order is load-bearing (2.2a §5):** emit the `id` text field, then the `timestamp`
  text field, **then** the file part — in that order. `@fastify/multipart`'s `req.file()`
  only exposes fields parsed _before_ the file part; a file-first body yields `undefined`
  metadata → 422 on every valid upload.
- `Content-Type: multipart/form-data; boundary=…`; the file part is `image/jpeg`.
- Bearer token from `AuthSession`; on 401, `forceRefresh()` then retry once (mirrors
  `TimeEntryUploader`). Reuse `UploadResult` + `TimeEntryUploader.classify` (or a shared
  copy) for status → result. Not a capture path itself → no `AckGate`.
- Signature: `func upload(id:String, capturedAt:Date, jpeg:Data) async -> UploadResult`
  (needs the fields, not just an opaque payload — so it does **not** conform to the JSON
  `Uploading` protocol; it has its own shape).

### 5.4 `ScreenshotSyncEngine` — `Sync/ScreenshotSyncEngine.swift`

A **parallel** drain engine mirroring the JSON `SyncEngine` (not a generalization of it —
lower risk, and 2.2a mandates a separate path):

- Self-scheduling timer (kick immediately, then interval; back off on failure). Also exposes
  `syncNow()` for an opportunistic drain kicked right after each capture and for the sign-out
  final drain.
- Drain: `take(limit:)` from `ImageBufferStore`, upload each; **remove on 201**, **drop on
  permanent 4xx** (poison record can't wedge the queue), **stop + `BackoffPolicy`** on
  transient/auth. `prune` stale each cycle.
- Not a capture path (uploads already-captured images) → **not** `AckGate`-gated, and (like
  the JSON `SyncEngine`) safe to run on both the online and offline-marker `becomeReady`
  branches.

### 5.5 `ScreenshotScheduler` — `Capture/ScreenshotScheduler.swift`

The capture trigger. **Chosen mechanism: a single self-gating interval timer** (over
start/stop plumbing driven off `TimeTracker` transitions — same outcome, less machinery, and
it mirrors the existing heartbeat timer that already guards on `timeTracker.isRunning`).

- One `Timer` at `screenshotIntervalMinutes` (resolved from policy at install).
- Each fire, in order:
  ```
  ackGate.withCaptureAllowed {
      guard timeTracker.isRunning        // cadence: only while tracking
      guard screenshotsEnabled           // PRD §6.2 disable-entirely
      let jpeg = try await grabber.grab()
      let id = UUIDv7.generate(now: capturedAt)
      buffer.enqueue(id:, capturedAt:, jpeg:)
      uploadEngine.syncNow()             // opportunistic drain
  }
  ```
- The per-tick `AckGate` fetch **re-checks the ack every interval** for free: mid-session
  ack-revocation stops capture at the next tick; offline → gate closes → capture skipped
  (fail-safe), tracking unaffected. (`AckGate` gates on `ackRequired` only; it does not hand
  settings to the body.)
- `screenshotsEnabled` and the interval are an **install-time snapshot** from the launch
  policy read — exactly like auto-tracking snapshots `idleThresholdMinutes`. The app has no
  periodic policy refresh today, so a mid-session enable/disable or interval change is picked
  up on the next launch / next tracking start, not on a live timer (§10). If
  `screenshotsEnabled` is false at install, the scheduler is simply never installed.
- On `grab()` failure due to **missing Screen Recording permission**, flip the menu-bar
  warning state (§5.6) and skip this tick; keep the timer running so capture self-heals when
  the user grants permission. Other grab errors are logged and skipped.

### 5.6 `ScreenRecordingPermission` — `Capture/ScreenRecordingPermission.swift`

- `isGranted()` via `CGPreflightScreenCaptureAccess()`; `request()` via
  `CGRequestScreenCaptureAccess()` (or the ScreenCaptureKit equivalent) — the system prompt;
  helper to open the System Settings > Privacy > Screen Recording pane.
- Drives a menu-bar warning state on `StatusItemController` (new state alongside the existing
  `showPolicyUnavailable()`), cleared once capture succeeds. Visible, dismissible-by-fixing,
  never blocks tracking.

## 6. Wiring (`AppDelegate`)

- **`EffectivePolicy.Settings`** gains `screenshotsEnabled: Bool` +
  `screenshotIntervalMinutes: Int` (server serializes both — §3). Because Swift `Decodable`
  **fails** on a missing declared key, these must always be present in `/policy/effective`
  (they are — required in `TeamSettingsSchema`, and effective policy returns full settings).
- **Capture scheduler** installs on the **online `!ackRequired` branch only**
  (`startAutoTrackingIfEnabled`'s sibling — the offline ack-marker must never open a capture
  path), behind `AckGate`, only if `screenshotsEnabled`. Install alongside auto-tracking.
- **Upload engine** starts in `startSyncIfNeeded` alongside the JSON `SyncEngine` (both
  branches — it is not a capture path).
- **Sign-out teardown** (cross-user integrity — server attributes by token, so a leftover
  image uploading under the next user is the same bug `flushAndClearBuffer` guards against):
  stop the scheduler, stop + best-effort final-drain the upload engine (needs the still-valid
  token → before `logout`), then **`ImageBufferStore.clear()`**. Fold into the existing
  sign-out sequence next to the JSON buffer flush.

## 7. Data flow

```
tick (every screenshotIntervalMinutes)
  └─ AckGate.withCaptureAllowed        ── closed if !acked/offline → skip, keep clock
       └─ guard tracking & enabled
            └─ grabber.grab()          ── JPEG (main display); no-perm → menu-bar warning
                 └─ ImageBufferStore.enqueue(id, capturedAt, jpeg)   ── durable, atomic
                      └─ uploadEngine.syncNow()                       ── opportunistic
                           └─ ScreenshotUploader.upload → POST /screenshots (id,timestamp,file)
                                └─ 201 → ImageBufferStore.remove(id)  ── delete-after-confirm
                                   transient/401 → keep, backoff, retry next cycle
                                   permanent 4xx → drop (poison)
```

## 8. Testing

XCTest with fakes — no display, no network (mirrors `SyncEngineTests` /
`BufferStoreTests`). `swift test` needs `DEVELOPER_DIR=Xcode` (known — the executable target
is `@testable`-importable).

1. **`ImageBufferStore`** (real files, tmp dir): enqueue→take round-trips id + `capturedAt` +
   bytes; FIFO order; `remove`; age-prune and count-prune; crash sweep of `.tmp-*`; `clear`.
2. **`ScreenshotUploader`**: multipart body construction asserts **`id` and `timestamp`
   precede the file part** (the 2.2a-binding invariant) and content types; `classify`
   reused/covered. Body build is testable without a network round trip.
3. **`ScreenshotSyncEngine`** with a `FakeImageUploader` + fake/real buffer: remove-on-201,
   drop-on-permanent, stop+backoff-on-transient, stop-on-authFailed, prune stale — mirrors
   `SyncEngineTests`.
4. **`ScreenshotScheduler`** with `FakeDisplayGrabber` + `FakePolicyProvider` (drives
   `AckGate`) + fake tracker/buffer: gate-closed → no grab; not-tracking → no grab;
   disabled → no grab; tracking+acked+enabled → grab enqueued and `capturedAt` stamped once
   and reused; grab-throws-no-permission → warning flagged, timer survives.
5. **`ScreenCaptureKitGrabber`** and the menu-bar warning wiring: **build-verified only**
   (real display + TCC), documented as not CI-runnable.

No new coverage gate: the 80% gate is `apps/api` + `packages/contracts`; the Swift client
runs XCTest without a coverage threshold (as the prior client slices did).

## 9. Boundaries / policy compliance (CLAUDE.md §1, §3)

- Every capture goes through **`AckGate`** — no bypass, no debug flag, no admin override.
- **Menu-bar indicator stays visible**; the permission warning is additive, never a hidden or
  stealth state, and has no capture kill-switch that hides the indicator.
- **No keystroke content, no webcam/audio/GPS/clipboard** — this slice adds screen image
  capture only, exactly as PRD §6.2 scopes.
- **Symmetric transparency:** the uploaded image is readable by the employee via the same
  `GET /screenshots` (self-scoped) a manager uses, with `fullUrl` for full-res (2.2a §8) —
  nothing captured is manager-only.
- **No raw image bytes logged** (Pino rule is server-side, but the client mirrors it): log
  `{ id, capturedAt, status }` only, never bytes.
- Client captures **raw**; blur/thumbnail-only is server policy (§2).

## 10. Deferred

- **Multi-display** capture (main display only in v1).
- **Mid-session `screenshotsEnabled` / interval change**: both are install-time snapshots
  (like auto-tracking's threshold), picked up on next launch / next tracking start, not on a
  live timer. Only ack-revocation is caught per tick (via the `AckGate` fetch). The app has
  no periodic policy refresh to hang a live re-read on today.
- **Dashboard** screenshot grid + redact button (2.2c).
- **Retention sweep** of old client-side images beyond the buffer bound (server retention is
  Phase 4).
