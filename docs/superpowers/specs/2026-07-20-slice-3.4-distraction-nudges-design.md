# Slice 3.4 — Distraction alerts (local, end-of-day) — design

**Date:** 2026-07-20
**Phase:** 3 (Reporting + approvals)
**Roadmap:** `docs/plans/phase-3-reporting-approvals.md` §Slice 3.4
**PRD:** §6.4 (idle/distraction, local-only), §6.3 (categorization), §4.3 (symmetric transparency), §11

---

## 1. Goal

Deliver **local, transparent** distraction nudges on the macOS client, closing out slice 3.4:

1. **Distraction nudge** — a gentle local notification when the employee spends a sustained stretch
   (10 consecutive minutes) on an **UNPRODUCTIVE** app/site (from the admin policy lists).
2. **End-of-day distraction tally** — today's unproductive time folded into the existing end-of-day
   summary notification ("Today: ~6h 12m tracked. Nice work. ~40m on distracting apps.").

The product intent is **trust, not surveillance** (PRD §6.4): nudges are **local and time-delayed**,
never streamed live to a manager. Managers only ever see distraction **in aggregate**, and only via
data that already exists — the 2.3a activity rollup (category-per-minute), which the client already
syncs. This slice adds **no** live feed and **no** new server surface.

**Client-only.** Like slice 2.4, this touches **no** `packages/contracts`, `packages/db`,
`apps/api`, `apps/worker`, or `apps/dashboard` — only `apps/client-macos`.

## 2. Current state (verified against the code, 2026-07-20)

Already built (this slice does **not** rebuild any of it):

- **Categorization (2.3b):** `Activity/Categorizer.swift` maps `(appName, host)` →
  `Category { productive | unproductive | neutral }` from the admin policy lists
  (`PolicyClient.Settings.productiveApps` / `unproductiveApps`). UNPRODUCTIVE wins on overlap
  (fail toward flagging). No content is read — only the app name and a transient host.
- **Activity capture (2.3a/2.3b):** `Activity/ActivitySampler.swift` — a self-gating ~60s interval
  timer that, **only while `isTracking()`** and **only through `AckGate`**, measures activity %,
  samples the frontmost app + (transiently) the browser host, **computes the `Category`**
  (line ~95), enqueues one `ActivitySample`, and kicks batch sync. Installed only on the live-policy
  `!ackRequired` path (`AppDelegate.installActivityCapture`). The category is already computed here;
  today it is only written into the synced sample and then discarded.
- **Local-notification infra (2.4):** `Notifications/LocalNotifier.swift` — the single
  `LocalNotifying` seam (`requestAuthorization` / `notify(id:title:body:)` / `clearAll`). The
  concrete `UNUserNotifier` uses a `lazy var center` so the `swift test` host (no bundle id) does
  not SIGABRT. Nudges are local; nothing here touches the network or logs.
- **End-of-day summary shell (2.4):** `Notifications/EndOfDayScheduler.swift` — a daily wall-clock
  timer that fires at `hour:00` local, reads today's tracked seconds via an injected
  `total: (Date) -> Int`, posts one summary notification (id `"end-of-day"`), and reschedules.
- **Nudge/tally patterns (2.4):** `Tracking/ManualNudgeMonitor.swift` (a pure `tick(...)` decision
  unit with a re-arm flag, timer-free and fully unit-tested) and
  `Tracking/DailyTotalAccumulator.swift` (a local-day tally fed by `TimeTracker.onSpanClosed`, with
  `reset()`). These are the exact shapes this slice mirrors.
- **Sign-out teardown (2.4):** `AppDelegate` stops the pollers and resets the accumulator on
  sign-out so a prior user's state never bleeds into the next sign-in.

Missing — the real 3.4 work (all net-new on the client):

- A distraction-detection decision unit (consecutive UNPRODUCTIVE → nudge).
- A local per-day unproductive-time tally.
- The `ActivitySampler` → distraction hook.
- The end-of-day summary distraction line.
- AppDelegate wiring + sign-out teardown for all of it.

## 3. Design overview

Two net-new units plus three small edits, all in `apps/client-macos/Sources/TimeTrack`. Everything
is fed off the `Category` `ActivitySampler` **already computes** — no second host-resolution path,
no new `AckGate` capture path, no new timer that runs when the employee is not tracking.

```
Tracking/DistractionMonitor.swift           NEW  pure tick(category:now:) → local nudge at threshold
Tracking/DailyDistractionAccumulator.swift  NEW  tallies today's unproductive seconds (local day)
Activity/ActivitySampler.swift              EDIT new optional onCategorized callback (default no-op)
Notifications/EndOfDayScheduler.swift       EDIT optional distractionTotal → summary line
App/AppDelegate.swift                        EDIT wiring + sign-out teardown
```

### 3.1 Data flow

```
ActivitySampler.captureTick()  (~60s window, only while tracking, only through AckGate)
  └─ category = categorizer.category(appName:, host:)      (existing, line ~95)
     └─ onCategorized(category)        ← NEW optional callback, default { _ in } (no call-site breakage)
          ├─ DistractionMonitor.tick(category:, now:)         → nudge at 10 consecutive UNPRODUCTIVE
          └─ if category == .unproductive:
               DailyDistractionAccumulator.addUnproductive(now:)   → +sampleSeconds to today's tally
```

`onCategorized` fires **only on a measured tick** — the same branch that enqueues a sample, after
`enqueue`/`onSampled`. It never fires on a skip path (not tracking, gate closed, cancelled), so the
distraction subsystem inherits the sampler's "only while tracking, only through the gate" scope for
free. The callback is invoked on the sampler's task; `AppDelegate` hops to the main actor before
touching the monitor/accumulator (both are main-thread-only, like `DailyTotalAccumulator`).

### 3.2 `DistractionMonitor` (pure decision unit — no timer, no network, no disk, no logging)

State:

- `unproductiveStreak: Int` — count of **consecutive** UNPRODUCTIVE samples seen.
- `firedThisStreak: Bool` — whether the nudge has already fired for the current streak.

`tick(category: Category, now: Date)`:

- `category == .unproductive`:
  - `unproductiveStreak += 1`.
  - if `unproductiveStreak >= threshold` **and** `!firedThisStreak`:
    - `notifier.notify(id: "distraction", title: "Time tracking", body: "~\(threshold) min on distracting apps — refocus?")`
    - `firedThisStreak = true`.
- `category != .unproductive` (PRODUCTIVE **or** NEUTRAL) → `unproductiveStreak = 0`,
  `firedThisStreak = false` (re-arm). **Conservative default: any non-distraction sample breaks the
  streak** (the advisor-endorsed simple rule — no cooldown/tolerance knob, YAGNI).

Fires **exactly once per streak**. After firing, no repeat until a non-unproductive sample resets
the streak and a fresh streak rebuilds to `threshold`.

`threshold` is the number of consecutive UNPRODUCTIVE samples (injected). Because `ActivitySampler`'s
window is 60s, `threshold = 10` ⇒ ~10 consecutive minutes. The 60s-cadence → minutes coupling is a
documented assumption; it lives in `AppDelegate` where the sampler is constructed.

`stop()` resets both state fields (mirrors `ManualNudgeMonitor.stop()`), for sign-out teardown.

`now` is currently unused by the decision (streak is count-based) but is kept in the signature to
match the `ManualNudgeMonitor.tick(...:now:)` shape and to leave room for a future time-based streak
without a signature change. _(Design note: count-based, not elapsed-time-based — a tracking gap
mid-streak simply produces no ticks; it neither advances nor resets the streak. Acceptable and rare.)_

### 3.3 `DailyDistractionAccumulator` (local-day tally — mirrors `DailyTotalAccumulator`)

- `addUnproductive(now: Date)` — adds `sampleSeconds` (injected, default 60 — one sampler window) to
  the tally for `now`'s **local** day; a `now` on a new local day rolls the tally over (prior day
  dropped — the summary is a nicety, not a record of truth).
- `todaySeconds(now: Date)` — the tally iff the stored day matches `now`'s local day, else 0.
- `reset()` — clears day + tally (sign-out teardown).

Not a capture path; touches no network, disk, or logging. Main-thread only.

### 3.4 End-of-day summary line

`EndOfDayScheduler.init` gains an optional `distractionTotal: (Date) -> Int = { _ in 0 }` (default
keeps every existing construction/back-compat). `fire()`:

```
base = "Today: ~\(formatDuration(total)) tracked. Nice work."
d = distractionTotal(now)
body = d > 0 ? base + " ~\(formatDuration(d)) on distracting apps." : base
```

Reuses the existing `formatDuration`. One notification, one daily ping (id `"end-of-day"`, unchanged).

### 3.5 `ActivitySampler` edit

Add `onCategorized: (Category) -> Void = { _ in }` to `init` (optional, defaulted — existing call
sites and tests compile unchanged, avoiding the required-init-param call-site landmine). Call
`onCategorized(category)` inside the measured branch, right after `onSampled()`. No other behavior
change; the category is already computed there.

### 3.6 `AppDelegate` wiring

- New constant: `distractionThresholdMinutes = 10` (documents the 60s-cadence → 10-samples coupling).
- In `installNudgeInfra` (runs where the `notifier` is created): create `distractionMonitor`
  (`DistractionMonitor(notifier:, threshold: distractionThresholdMinutes)`) and
  `dailyDistraction` (`DailyDistractionAccumulator()`); pass `dailyDistraction.todaySeconds` as the
  new `distractionTotal` into `EndOfDayScheduler`.
- In `installActivityCapture`, set the sampler's `onCategorized` to hop to the main actor and call
  `distractionMonitor.tick(category:, now:)` and, on `.unproductive`,
  `dailyDistraction.addUnproductive(now:)`.
- Sign-out teardown: `distractionMonitor?.stop()`, `dailyDistraction?.reset()`, nil both — mirroring
  the existing `manualNudgeMonitor` / `dailyTotal` teardown. **This is the load-bearing guard against
  the sign-out-leak bug class** (a prior user's streak/tally bleeding into the next sign-in).

## 4. What this slice explicitly does NOT do

- **No real-time manager feed of distraction events.** A deliberate product constraint (PRD §6.4).
  No live endpoint, no new contract, no new sync path. If the design ever seems to require reaching
  for `packages/contracts`, it has misread the slice.
- **No new capture path.** Detection piggybacks on the existing gated `ActivitySampler`; it adds no
  `AckGate.withCaptureAllowed` call and no timer that runs when the employee is not tracking.
- **No content.** The monitor sees only a `Category` enum value — never an app name, host, window
  title, or keystroke content.
- **No cooldown/tolerance/second-threshold knobs.** YAGNI: any non-unproductive sample breaks the
  streak; one nudge per streak.

## 5. Testing (XCTest — all pure/deterministic, using the existing `SpyNotifier`)

- **`DistractionMonitorTests`:**
  - 10 consecutive UNPRODUCTIVE ticks → **exactly one** `"distraction"` nudge (9 ticks → none).
  - A PRODUCTIVE tick before threshold resets the streak (no nudge); likewise a NEUTRAL tick.
  - After firing, further UNPRODUCTIVE ticks do **not** re-fire; a non-unproductive tick then a fresh
    run to threshold fires again (re-arm).
  - `stop()` clears state (a post-`stop()` run must rebuild from zero).
- **`DailyDistractionAccumulatorTests`:** accumulates within a local day; rolls over on day change;
  `todaySeconds` returns 0 on a stale day; `reset()` zeroes it.
- **`EndOfDaySchedulerTests` (extend):** `fire()` body includes the `"on distracting apps"` line when
  `distractionTotal > 0` and omits it when 0; the tracked-time sentence is unchanged.
- **`ActivitySamplerTests` (extend):** a measured tick invokes `onCategorized` with the computed
  category; a skip path (not tracking) does not.

**"Nothing is sent to the server in real time" holds by construction** — `DistractionMonitor` and
`DailyDistractionAccumulator` have **no** network seam (they depend only on `LocalNotifying` and a
clock). There is nothing to mock and no request to assert; the absence is structural, so the spec
states it rather than writing a hollow "assert no request" test.
