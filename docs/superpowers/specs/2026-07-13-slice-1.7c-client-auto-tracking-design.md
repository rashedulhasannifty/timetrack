# Slice 1.7c — Automatic tracking — Design

**Date:** 2026-07-13
**Slice:** 1.7c (macOS client MVP — automatic tracking)
**Branch:** `slice-1.7c-client-auto-tracking`
**Predecessor:** 1.7b (menu bar + manual tracking — done)

---

## 1. Goal & scope

Layer active-app / idle-based **automatic** tracking on top of 1.7b's manual tracker. When a
team enables `autoStartOnLogin`, a ready employee's time is tracked automatically: an `AUTO`
`TimeEntry` starts when the client becomes ready, auto-stops on idle / system sleep / screen
lock, and on resume the employee is asked "away for X min — keep or discard?" (discard is the
default). Each away period is recorded as an `IdleEvent`.

Automatic tracking reads hardware/OS signals (`CGEventSource` idle time, `NSWorkspace` active
app / sleep / lock), so — per `AckGate.swift`'s own contract ("screenshot, activity sampling,
and **idle detection** all route through here") and CLAUDE.md §1 — it is a **capture** path.
Unlike manual tracking it is gated by `AckGate` and therefore **does not run offline**.

**In scope**

- `Tracking/IdleMonitor` — the pure idle **state machine** (active → idle → resume →
  keep/discard), injectable clock + threshold, driven by fed idle-seconds and sleep/wake/resume
  signals. This is the unit the required XCTest drives.
- `Tracking/WorkspaceObserver` — the system edge: `NSWorkspace` activate / `willSleep` /
  screen-lock notifications + a timer polling `CGEventSource` idle seconds; feeds `IdleMonitor`.
- `App/AutoTrackingCoordinator` — wires `IdleMonitor`'s decisions to `TimeTracker`, the buffer
  (`IdleEvent`), the current picker selection, and the keep/discard prompt.
- Auto-start / auto-stop lifecycle producing `source: AUTO` `TimeEntry` records and `IdleEvent`
  records, both **enqueued** to the buffer (sync is 1.7d).
- Keep/Discard-on-resume prompt UI (discard default).
- Decoding `settings` (`idleThresholdMinutes`, `autoStartOnLogin`) from `GET /v1/policy/effective`
  — the server already sends it; the client just isn't reading it yet.
- Gating: auto-tracking is activated only through `AckGate.withCaptureAllowed`, only on the
  live-policy `!ackRequired` branch. Manual tracking stays ungated and offline-capable.

**Out of scope (later slices / phases)**

- Activity-% sampling, keyboard/mouse event counts, app/site categorization, window titles
  (Phase 2, §6.3). `WorkspaceObserver` in 1.7c only signals activity/sleep/lock — it records no
  app data.
- The actual sync drain / `POST /v1/time-entries` / an idle-event endpoint (1.7d). 1.7c only
  **enqueues** to `BufferStore`.
- Idle / distraction **notifications** ("Idle for X min — still working?", §6.4) — Phase 2.
- Any new **local** Settings UI or per-user override. Auto-tracking is governed solely by the
  team `autoStartOnLogin` setting for 1.7c (see §7, decision 3).
- Screenshot capture and the "Capturing" icon state (Phase 2).

## 2. Constraints (carried from 1.7a/1.7b + CLAUDE.md/PRD)

- **No new SwiftPM dependency.** Idle time via `CGEventSource`, activity/sleep/lock via
  `NSWorkspace`, UUIDv7 hand-rolled (existing), IdleEvent JSON via Foundation. (CLAUDE.md §2)
- **`AckGate` stays the single structural gate for capture, and is untouched.** Auto-tracking
  is capture and routes through `AckGate.withCaptureAllowed`. No bypass, no admin override, no
  debug flag is added. (CLAUDE.md §1, PRD §4.1)
- **The offline ack marker never opens a capture path.** It re-enables *manual* tracking
  offline (1.7b); it must not start auto-tracking. (Carried invariant — see §5.)
- **The menu-bar indicator is always visible; no stealth, no kill switch.** Auto-tracking only
  ever drives the icon between idle and tracking. (CLAUDE.md §1, PRD §4.2)
- **No key/pointer content is ever read.** `IdleMonitor` consumes only an idle-**seconds**
  scalar; there is no code path to event content. (CLAUDE.md §1, PRD §6.3)
- **All API routes are under `/v1`.** The injected base URL already carries it. (CLAUDE.md §4)
- **Tests reach the module via `@testable import TimeTrack`**; client tests run via
  `swift test` from `apps/client-macos` (needs `DEVELOPER_DIR=<Xcode>` — CommandLineTools lacks
  XCTest), outside `pnpm test`.
- **Commits:** Conventional Commits, scope `client`, no AI attribution. (CLAUDE.md §0)

## 3. Architecture

The slice keeps the 1.7a/1.7b shape: small units behind protocols, a thin `AppDelegate` that
wires them, UI kept out of the logic. Two new tracking units (`IdleMonitor`, `WorkspaceObserver`)
plus a coordinator sit alongside the existing `TimeTracker`.

```
                     idle seconds (timer)          activate / willSleep / screenLock
┌──────────────────┐  ─────────────┐           ┌──────────────────────────────────┐
│  CGEventSource   │               │           │            NSWorkspace            │
└──────────────────┘               ▼           └──────────────────┬───────────────┘
                          ┌───────────────────┐                   │ signals
                          │ WorkspaceObserver │ ◀─────────────────┘
                          │  (system edge)    │
                          └─────────┬─────────┘
                        tick(idleSeconds:) / sleep / wake / resume
                                    ▼
                          ┌───────────────────┐   delegate callbacks   ┌────────────────────────┐
                          │    IdleMonitor    │ ─────────────────────▶ │ AutoTrackingCoordinator│
                          │ (pure state m/c)  │ ◀── resolve(.keep/.    │  (IdleMonitorDelegate) │
                          └───────────────────┘      discard) ───────  └───────────┬────────────┘
                                                                          │ start(source:.auto) │
                                          ┌───────────────────────────────┤ stop(at:) recordSpan│
                                          │ selection                     │ enqueue IdleEvent    │
                                          ▼                               ▼        ▼
                                  ┌───────────────┐                ┌─────────────┐ ┌─────────────┐
                                  │ MenuViewModel │                │ TimeTracker │ │ BufferStore │
                                  └───────────────┘                └─────────────┘ └─────────────┘
                                                                          │ AwayResolutionView
                                                                          ▼ (keep / discard prompt)
```

`AppDelegate` (1.7a/1.7b) resolves auth → policy → ack. On the **online** `!ackRequired`
success branch — and *only* there — it calls `ackGate.withCaptureAllowed { … }` to activate
auto-tracking when `settings.autoStartOnLogin` is true, passing the team's
`idleThresholdMinutes`. On the offline-marker branch (or when `autoStartOnLogin` is false),
auto-tracking is never started; manual tracking behaves exactly as in 1.7b.

### Components

| Unit | New / edit | Responsibility |
| --- | --- | --- |

| `Tracking/WorkspaceObserver.swift` | new | System edge. Subscribes to `NSWorkspace.didActivateApplicationNotification`, `willSleepNotification`, and the screen-lock distributed notification; runs a repeating timer sampling `CGEventSource.secondsSinceLastEventType(.combinedSessionState, .null)`. ## 4. The idle state machine & reconciliation (load-bearing decision)

Resolved from the authoritative **PRD §6.1** ("auto-stop after idle threshold", "on resume: keep
or discard? — discard is the default") reconciled with the `packages/contracts/src/idle.ts`
contract ("`DISCARDED` means the overlapping auto-tracked time is dropped"). The **client is
authoritative**: it produces correct `TimeEntry` boundaries *and* an `IdleEvent` audit record, so
Phase-1 behavior is correct without any (not-yet-built) server-side netting.

### States

`idle` → `active(auto entry running)` → `away(awayStart)` → (prompt) → back to `active` or `idle`.

- **Activate (ready, online, acked, `autoStartOnLogin`)** — via `AckGate`; `TimeTracker.start(source: .auto)`
  using the current picker selection. State `active`.
- **Idle detected** — a `tick(idleSeconds:)` where `idleSeconds ≥ thresholdSeconds`. The away
  period began at `awayStart = clock() − idleSeconds` (last-input time). Delegate `autoStop(at: awayStart)`
  → `TimeTracker.stop(at: awayStart)` (auto-**stop**, per PRD; the entry excludes the idle tail).
  State `away(awayStart)`.
- **System sleep / screen lock** — `systemDidSleep()`. Input stops now, so `awayStart = clock()`.
  Same `autoStop(at: awayStart)`. State `away(awayStart)`.
- **Resume** — first input/activity after `away` (or `systemDidWake()` followed by activity), at
  `Tr`. Delegate `promptAwayResolution(awaySeconds: Tr − awayStart)`.
  - **Discard (default)** — no bridge entry (the away span stays an uncounted gap) +
    `IdleEvent(awayStart, Tr, DISCARDED)` + `TimeTracker.start(source: .auto)` (a fresh entry at Tr).
  - **Keep** — `TimeTracker.recordSpan(start: awayStart, end: Tr, source: .auto, …)` (a contiguous
    bridge entry so the away time is counted) + `IdleEvent(awayStart, Tr, KEPT)` +
    `TimeTracker.start(source: .auto)`.
  - **App terminates mid-`away`** — the coordinator, on teardown, enqueues
    `IdleEvent(awayStart, <last known>, UNRESOLVED)` and **no bridge** (idle not counted — the
    fail-safe, consistent with discard-default). The already-closed entry (stopped at `awayStart`)
    is intact.

This mirrors 1.7b's manual pause=close / resume=new-entry pattern exactly (each contiguous span is
one `TimeEntry` keyed by a client-minted UUIDv7). `TimeEntry` boundaries carry the counted time;
the `IdleEvent` is the durable record the contract requires — the two never double-count because
the client, not the server, performs the netting in Phase 1.

### Manual-session coexistence

`IdleMonitor`/the coordinator **only manage an `AUTO` session**. If a `MANUAL` session is live
(the employee clicked Start themselves), the auto layer stands down: it does not auto-stop or
clobber the manual entry. `TimeTracker.State.tracking` carries the `source` so the coordinator can
tell. (Idle *notifications* for manual sessions are §6.4 / Phase 2.)

### Away-start precision

`awayStart` is `clock() − idleSeconds` for the idle-threshold path (so the closed entry excludes
the whole idle tail, not just the time past the threshold) and `clock()` for the sleep/lock path
(input demonstrably stopped at sleep). Both are computed inside `IdleMonitor` from injected inputs,
keeping the unit deterministic under test.

### Buffered payloads

`TimeEntry` — unchanged shape from 1.7b, now with `source: "AUTO"`:

```json
{ "id": "<uuidv7>", "projectId": "<uuid|null>", "taskId": "<uuid|null>",
  "startTime": "<iso8601>", "endTime": "<iso8601>", "source": "AUTO", "note": null }
```

`IdleEvent` — matching `IdleEventSchema`:

```json
{ "id": "<uuidv7>", "startTime": "<iso8601>", "endTime": "<iso8601>",
  "resolvedAction": "KEPT" | "DISCARDED" | "UNRESOLVED" }
```

> **1.7d note (not built here):** both kinds land in the same `BufferStore`. The payloads are
> self-describing (`source` vs `resolvedAction`), but 1.7d's `SyncEngine` will need to route each
> to its endpoint (`POST /v1/time-entries` vs the idle-event endpoint). Flagged, not solved, in
> this slice.

## 5. Gating — the carried invariant

- **Manual tracking:** unchanged. Not a capture path, not gated, offline-capable via the ack
  marker (1.7b).
- **Auto-tracking:** activated **only** through `ackGate.withCaptureAllowed { … }`, and **only**
  on `proceedToPolicy()`'s online `!ackRequired` success branch. It is **never** started inside
  `becomeReady()` — `becomeReady()` is *also* reached by the offline-marker `catch` branch, and
  activating there would let the local marker silently start capture, breaking the 1.7b invariant
  that "the marker never opens a capture path."
- Offline / policy-unavailable → `AckGate`'s live policy fetch throws → auto-tracking does not
  start, while manual tracking continues. Fail-safe.
- On sign-out, `AppDelegate` calls `coordinator.stopAutoTracking()` (tears down the observer/timer
  and resolves any pending away as `UNRESOLVED`) as part of the existing reset.
- `AckGate` itself is not modified.

`AckGate.withCaptureAllowed` performs one extra live policy fetch at activation (on top of the one
`proceedToPolicy` already did). That is accepted: it keeps the structural gate literal — capture is
started *through* the gate, not merely near it.

## 6. Keep/Discard prompt UI

A small SwiftUI view (`AwayResolutionView`) hosted in a lightweight window/panel, styled with
`TimeTrackTokens`:

- Title: "You were away" · body: "Away for **X minutes** while tracking. Keep this time or
  discard it?"
- Two buttons: **Discard** (default / highlighted, per PRD §6.1) and **Keep**.
- Dismissing the panel (Esc / close) resolves as **Discard**.
- The result flows back to `IdleMonitor.resolve(.discard | .keep)` via the coordinator.

No stealth surface; the panel is a normal, visible window. The always-visible status icon is
unaffected (it shows idle while away).

## 7. Decisions captured during design

1. **Auto-start trigger = on-ready + resume-from-idle.** When `autoStartOnLogin` is on and the
   client is ready (online, acked), start an `AUTO` entry immediately; after an idle gap, resume
   (via input/app activity) starts a fresh `AUTO` entry (following the keep/discard prompt).
2. **`AUTO` entry project = inherit current picker selection** (null if nothing selected). The
   employee can pre-pick a project and have auto-tracking attribute to it.
3. **Config scope = team setting only.** Governed purely by `EffectivePolicy.settings.autoStartOnLogin`
   from the policy fetch. No new local Settings UI / override in 1.7c.
4. **Reconciliation = client-authoritative** (Keep = contiguous bridge entry, Discard = uncounted
   gap; both emit an `IdleEvent`). No dependency on server-side netting.
5. **`AckGate` gating** confirmed by `AckGate.swift`'s own contract + CLAUDE.md §1: auto-tracking
   is capture, gated, and does not run offline.

## 8. Testing

**XCTest (unit) — `@testable import TimeTrack`, `swift test` (with `DEVELOPER_DIR=<Xcode>`):**

- **`IdleMonitorTests` (the required idle state machine):** with a fake `IdleMonitorDelegate`,
  injected clock, and fed idle-seconds —
  - `active` → `tick(idleSeconds: threshold)` → `autoStop(at:)` called with `awayStart = now − idleSeconds`.
  - `systemDidSleep()` → `autoStop(at: now)`.
  - resume after `away` → `promptAwayResolution(awaySeconds:)` fired once.
  - `resolve(.keep)` → `recordSpan(start: awayStart, end: resume, source: auto)` + `IdleEvent KEPT` + restart.
  - `resolve(.discard)` → **no** bridge + `IdleEvent DISCARDED` + restart.
  - teardown mid-`away` → `IdleEvent UNRESOLVED`, no bridge.
  - sub-threshold ticks do **not** transition to `away`.
- **`TimeTrackerTests` (edit):** `start(source: .auto)` records the source and the enqueued payload
  carries `source: "AUTO"`; `stop(at:)` backdates `endTime`; `recordSpan` enqueues exactly one
  complete entry with the given bounds; manual path (`source` default) still emits `MANUAL`.
- **Policy decode test:** an effective-policy JSON with `settings` decodes `idleThresholdMinutes`
  and `autoStartOnLogin`; a policy JSON missing `settings` fails closed / is handled.
- **`WorkspaceObserver`** and **`AwayResolutionView`**: build-verified (system/UI edges), exercised
  in the manual smoke.

**Manual smoke (end-to-end) — recorded, not fabricated:** infra + API up; seed a team with
`autoStartOnLogin=true` and a small `idleThresholdMinutes`; sign in as an acked user →
- AUTO tracking starts on ready (icon tracking; buffer shows an `AUTO` entry).
- Stop touching the machine ≥ threshold → auto-stops (icon idle; entry closed at away-start).
- Resume → keep/discard prompt → choose each path once → confirm buffer holds the expected
  `TimeEntry`s (Keep → bridge span present; Discard → gap) + an `IdleEvent` with the right
  `resolvedAction`.
- Lock the screen while tracking → auto-stops; unlock → prompt.
- Kill the API (offline) and re-launch → confirm auto-tracking **does not** start, while **manual**
  Start/Stop still works.
