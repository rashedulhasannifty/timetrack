# Slice 1.0 — Testcontainers harness + seed admin

**Status:** design approved (dependency asks resolved 2026-07-12)
**Plan:** `docs/plans/phase-1-mvp.md` (foundational slice ahead of 1.1; harness consumed by 1.4/1.6)

## Goal

Provide the two foundations the numbered Phase-1 slices depend on:

1. A **reusable Postgres Testcontainers harness** so integration/e2e specs run against a
   real Postgres 18 (never a mocked Prisma — `CLAUDE.md §5`).
2. An **idempotent bootstrap-ADMIN seed** driven by env, so the first ADMIN exists without
   hand-inserting rows (`phase-1-mvp.md` Slice 1.1 step 5, pulled forward).

## Non-goals

- **Completing the `time-entries` e2e suite.** The plan assigns "flip the gated spec into a
  real suite" to **Slice 1.4**. Slice 1.0 proves the harness with one minimal smoke test only.
- **Redis in the harness.** Nothing in 1.0/1.4 touches Redis; the first real need is 1.1's
  invite-email queue. Deferred — the harness is factored so a Redis container slots in as a
  small, localized change when 1.1 needs it. (Decision: defer, 2026-07-12.)

## Decisions (resolved)

- **`@testcontainers/redis`** — deferred to Slice 1.1 (build PG-only now).
- **`argon2` in `packages/db`** — added. Declared explicitly in `packages/db/package.json`
  (not relied on via hoisting). Same package AuthService uses; enables env-based seed hashing.

## Components

### 1. DB harness — `apps/api/test/db-harness.ts`

App-local, **not** a shared `packages/*` util: a shared package would have to import
`@timetrack/db`, which the no-cross-package-import rule (`CLAUDE.md §3`) forbids. So the
harness lives with the specs that use it, in `apps/api`.

Per-file container (consistent with `fileParallelism: false` in `vitest.e2e.config.ts`):

```
startTestDb(): Promise<TestDb>
  1. start `postgres:18-alpine`
  2. process.env.DATABASE_URL = container.getConnectionUri()
  3. spawn `pnpm --filter @timetrack/db exec prisma migrate deploy`
     (child inherits DATABASE_URL; prisma.config.ts reads it via env('DATABASE_URL')
      and dotenv never overwrites an already-set env var — verified)
  4. construct client: new PrismaClient({ adapter: pgAdapter(url) })
  5. return { prisma, url, close() }   // close(): $disconnect + container.stop()

truncateAll(prisma): Promise<void>    // between-test isolation
```

`@testcontainers/postgresql` is already a devDep of `apps/api` — no new test-infra dep.

### 2. Seed — `packages/db/prisma/seed.ts`

Extract a pure, reusable function so both the seed script and the smoke test call it (no
shelling out to the script from the test):

```
seedAdmin(prisma, { email, password, name?, teamId }): Promise<User>
  - argon2.hash(password, { type: argon2.argon2id })   // matches AuthService
  - idempotent upsert on `email` (create with role=ADMIN, teamId; update leaves hash as-is
    unless re-seeding is intended — upsert `update: {}` keeps it idempotent)
```

`seed.ts` `main()`:

- Keeps the existing idempotent Team upsert.
- Reads `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` **directly from `process.env` and guards**:
  if either is absent, skip admin creation (stays optional; `pnpm db:seed` still works with
  no admin configured). The seed cannot `import @timetrack/config` (packages don't import each
  other except `contracts`), so it validates inline (presence + basic length), not via `loadEnv`.

### 3. Env placement — `packages/config` + `.env.example`

To satisfy the env-placement rule (`CLAUDE.md §3`), add to the config `EnvSchema` as
**optional**:

- `SEED_ADMIN_EMAIL: z.email().optional()`
- `SEED_ADMIN_PASSWORD: z.string().min(8).optional()`

These are documentation-only for the seed's path (the API runtime ignores them, and the seed
reads `process.env` directly) — but they keep the canonical env list complete and are mirrored
in `.env.example` with commented example values.

### 4. Proof-of-life test — `apps/api/test/db-harness.e2e-spec.ts`

Gated by `RUN_E2E=1` (same pattern as the existing `time-entries.e2e-spec.ts`), so default
`pnpm test` / `pnpm test:e2e` stay green without Docker:

```
beforeAll: db = await startTestDb()
afterAll:  await db.close()

it('seeds an ADMIN whose password verifies'):
  - seed a team, then seedAdmin(db.prisma, { email, password, teamId })
  - assert the users row exists with role ADMIN
  - assert argon2.verify(hash, password) === true
```

One test exercises the harness end-to-end **and** validates the seed hashing.

- `pnpm lint && pnpm typecheck && pnpm test && pnpm build` — green (e2e gated off by default).
- `RUN_E2E=1 pnpm --filter @timetrack/api test:e2e` — harness smoke test passes with Docker up.

## Done when

- A shared `startTestDb()` harness boots real Postgres 18 + runs migrations + yields a Prisma
  client, and a gated smoke test proves it.
- `seedAdmin(...)` creates a bootstrap ADMIN idempotently from env; the smoke test confirms the
  hashed password verifies via `argon2.verify`.
- `argon2` declared in `packages/db`; `SEED_ADMIN_*` in the config schema + `.env.example`.
